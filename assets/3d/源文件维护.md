## 下次怎么维护

1. 每个对象使用明确的当前工作文件；重要里程碑另存到仓库外的日期归档。
2. 归档时在 Blender 使用“文件 → 外部数据 → 将资源打包”，另存副本，再重新打开确认。关联库、视频或模拟缓存可能需要额外复制，不能只凭保存成功判断完整。
3. 同时保存生成 / 导出脚本，记录对应游戏模型和未解决问题。使用脚本前先看它是否会清空重建场景。
4. `.blend1` 是自动备份。当前工作文件与归档都能打开后，可按需要清理重复备份；不同设计方案不要仅按文件名删除。
5. 重要里程碑归档额外复制到外部硬盘或你选定的云盘；同一块硬盘上的两个目录不能抵御硬盘故障。
6. 删除 worktree 前先查忽略文件、保存本地变化；“工作目录干净”不意味着没有本地源文件。

## 本轮 worktree 恢复

外部归档中 `worktree-manifest.json` 记录旧目录、分支、HEAD、保存的完整非忽略文件树和 `refs/archive/worktree-cleanup-20261022/*` 恢复引用。忽略的检查日志等保存在 `worktree-local-files/`；可重建的 `.godot`、依赖缓存和 Python 缓存不保存。

`repository.bundle` 保存清理前所有 Git 引用，可用 `git bundle verify <路径>` 检查。恢复目录时按清单选择 archive_ref：

```sh
git worktree add --detach /你选择的恢复目录 refs/archive/worktree-cleanup-20261022/分支名中的斜杠改为双下划线
```

这个恢复版本包含整理时未提交的非忽略文件；按需要将 `worktree-local-files/` 中相应目录复制进去。本轮保留远端分支和开放 PR，不将删除本地目录当成 PR 验收或合并。


临时 `codex/snapshot-source-20261022-0` 至 `-7` 分支清理后，对应提交保留在 `refs/archive/worktree-cleanup-20261022/snapshot-source-0` 至 `-7`。旧来源记录中的分支名称是历史名称；恢复包也保留了原名称。
