# 素材库

更新日期：2026-10-13

本作所有美术素材的**唯一存放处**。任务的内容与要求见[《美术任务书》](../docs/任务/美术任务书.md)；本文件只规定素材怎么生成、怎么命名、怎么保存。

## 1. 谁来做、用什么做

| 素材 | 工具 | 说明 |
| --- | --- | --- |
| 图像（人物设定、物证、纸张、界面、窗外景、绘本画稿、宣传图） | **Codex 内置图像生成**，经 `tools/art/art.py gen` 调用 | 提示词先写成文件，再生成；每次生成自动登记 |
| 3D（房间、道具、人物） | **Blender**，由 agent 用 computer use 在真实 Blender 界面中操作 | 建模步骤尽量写成脚本保存在 `scripts/`，可复现 |
| 排版（绘本页面、文字层） | 程序脚本 | 文字永远不交给图像模型画 |

## 2. 目录

```
assets/
├── README.md            本文件
├── 登记表.csv           每个素材一行：编号、任务、状态、版本、文件、提示词、参考图、工具、日期、游戏路径
├── _共用/               共用的风格前缀提示词、人物参考图
├── _归档/               推翻或废弃的旧素材（不进 git，不删除）
├── 2d/<任务编号-名称>/
│   ├── prompts/         提示词文件（进 git）
│   ├── drafts/          每次生成的草稿与日志（不进 git）
│   └── final/           定稿（进 git）
└── 3d/<任务编号-名称>/
    ├── scripts/         Blender Python 脚本（进 git）
    ├── source/          .blend 源文件（不进 git，本机保存）
    ├── export/          导出的 .glb（进 git）
    └── preview/         预览截图（进 git）
```

## 3. 流程

1. **写提示词**：`2d/<任务>/prompts/<素材编号>.txt`。开头贴 `_共用/` 里对应的风格前缀，再写这一张的内容。提示词用英文写画面，禁止让模型画正文文字。
2. **生成草稿**（每张约 70 秒；多张可以并行，登记表有文件锁）：
   ```bash
   python3 tools/art/art.py gen 2d/T-024-人物三视图 grey_sheet assets/2d/T-024-人物三视图/prompts/grey.txt --ref assets/2d/T-024-人物三视图/底脸.png --title "格雷三视图"
   ```
   草稿存到 `drafts/<编号>-v<N>.png`，自动在登记表加一行（状态“草稿”）。同一编号再生成一次就是 v2、v3。
3. **挑选与定稿**：用户（或 agent 按验收清单）选定一个版本：
   ```bash
   python3 tools/art/art.py promote char_barlow v2 [--max 2048] [--png] [--game godot/art/...]
   ```
   存为 `final/<编号>.jpg`（质量 92；需要透明背景时加 `--png`），状态改为“定稿”；加 `--game` 时同时复制到游戏工程，并记下游戏路径。
4. **查看**：`python3 tools/art/art.py ls [2d/T-024-人物三视图]`。

## 4. 命名

- 任务目录：`<任务编号>-<中文名>`，如 `2d/T-024-人物三视图`。
- 素材编号：小写英文加下划线，与《美术任务书》中给出的文件名一致，如 `photo_1901_a`、`ad_butler`。
- 版本：`v1`、`v2`……只增不改。

## 5. 保存规则

| 内容 | 进 git | 理由 |
| --- | --- | --- |
| 提示词、登记表、脚本、README | 是 | 体积小，是复现素材的依据 |
| 定稿图片（JPEG，通常 0.1—0.5 MB）、导出的 .glb、预览图 | 是 | 游戏与参赛材料需要 |
| 草稿、生成日志 | 否 | 数量多、体积大；本机保留，登记表里有记录 |
| .blend 源文件、超过 10 MB 的母版 | 否 | GitHub 单文件上限 100 MB；本机保留 |
| `_归档/` | 否 | 废弃但不删除 |

- 生成原图是 PNG（每张 2—4 MB），只留在 `drafts/`；进 git 的是定稿 JPEG。需要透明背景的（纸张、印章）用 `--cutout` 存透明 PNG，每张约 2—3 MB。
- 由定稿再加工出的文件（裁切、拼版）也放进 `final/`，并在登记表补一行，`tool` 列写明“由 xxx 裁切”。
- 不进 git 的内容只存在本机，**需要额外备份**（见第 6 节）。
- 参赛要求注明素材来源：登记表的 `tool`、`prompt`、`refs` 三列就是来源记录，不要手动删改。

## 6. 维护与备份（10-13 用户确定）

- **GitHub 维护素材库**：第 5 节中“进 git”的内容（提示词、登记表、脚本、定稿、导出的 .glb、预览图）随项目一起提交、推送，GitHub 上的版本就是素材的正式版本。
- **本机保存源文件**：.blend 源文件、生成草稿、母版与 `_归档/` 只放在本机，不进 GitHub，也不使用 Git LFS。
- 因为源文件只在本机：定稿与导出一定要及时提交；任何定稿都能通过登记表里的草稿路径和提示词在本机找回或重新生成。
