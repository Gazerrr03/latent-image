# 1.4 空间与地图

负责：地图 / 3D 美术。表格在 `godot/content/space/`，模型交到 `incoming/models/`。

在美术模型做好之前，游戏用**灰盒**（方块）按这两张表把房间搭出来。所以地图成员不用等建模，先填表就能在游戏里走进自己设计的房间，调整布局、机位和光线。

## 房间登记表 `rooms.csv`

**一行 = 一个房间。**

| 列 | 中文意思 | 怎么填 |
| --- | --- | --- |
| id | 编号 | 英文，如 `butler_room` |
| name | 名称 | 管家室与钥匙房 |
| width, height, depth | 宽、高、深 | 米。宽沿 x，深沿 z |
| model | 美术模型 | 模型到位后由程序填写，如 `res://art/rooms/room_study.glb`。有模型时用模型，没有时用灰盒 |
| note | 备注 | — |

## 房间布局表 `layout.csv`

**一行 = 房间里的一样东西。** `type` 列决定这一行是什么：

| 类型 | 是什么 | 要填的列 |
| --- | --- | --- |
| 家具 | 灰盒方块（桌子、书架、窗、镜子……） | id 写名称；x, z 是中心位置，**y 是底部离地高度**；w, h, d 是宽、高、深；color 颜色 |
| 可检查物件 | 玩家能检查的东西 | id 写可检查物件表里的编号（`hs_` 开头）；x, y, z 是它的中心 |
| 机位 | 镜头模式下摄像机的位置 | id 写机位名（镜头表 camera 列用它）；x, y, z 是摄像机位置；look_x, look_y, look_z 是它看向的点 |
| 灯光 | 点光源 | x, y, z 位置；color 光色；energy 亮度（1—4 常用） |
| 出生点 | 行走模式开始时玩家站的地方 | id 写 `spawn`；x, y, z 是脚下位置；look_x, look_y, look_z 是一开始看向的点 |

坐标约定见[填表说明首页](README.md)。

### 示例（管家室的一部分）

```
butler_room,出生点,spawn,0,0,2.5,,,,0,0,1.5,,,
butler_room,灯光,,2.0,1.6,-2.6,,,,,,,#ffb070,1.4,
butler_room,家具,钥匙钩板,2.0,1.2,-2.9,1.4,0.6,0.06,,,,#5b3f2a,,
butler_room,可检查物件,hs_key_tags,2.0,1.5,-2.8,0.3,0.3,0.3,,,,,,
butler_room,机位,door_push,0,1.6,2.6,,,,-0.5,0.8,-1.5,,,
```

### 关卡设计提示

- 依据《03-空间与关卡设计》第 5 节：每个房间有一个开放式问题和三件关键物件。
- **指引靠光**：把房间里唯一的暖光放在关键物件旁边。
- 可检查物件放在离地 0.6—1.8 米之间，玩家站着就能看到。
- 改完表，在游戏里按 F1 → “重载内容表”，再跳到对应镜头，就能看到变化。

## 房间模型（3D 美术）

模型做好后，按《09-团队协作与任务派发》第 5 节的命名约定导出 `.glb`，交到 `incoming/models/`。模型里的 `hs_` 物件、`spawn`、`cam_` 机位会自动识别，与布局表里的同名项对应。

## 常见错误

- 家具的 y 填成了中心高度，结果方块一半埋在地下。
- 可检查物件放进了家具里面，玩家视线被挡住检查不到。
- 机位放在墙外，画面一片黑。
