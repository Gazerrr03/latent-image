# 1.4 空间与地图

> **10-14 起：关卡空间与镜头构图由人在 Godot 编辑器里把控，不再填表。** 填表只用于线索（1.3）和小物件资产（本页第 3 节）。

负责：用户（关卡空间与机位构图）；3D 美术（按关卡读出的规格做小物件模型）。

## 1. 什么填表，什么由人在编辑器里把控

| 内容 | 怎么做 | 原因 |
| --- | --- | --- |
| 房间的尺寸、墙、家具、灯光、动线 | 在 Godot 里搭关卡场景 | 影响核心体验，要看着调 |
| 机位的位置、角度、焦距 | 关卡场景里的 `Camera3D` 节点 | 同上 |
| 可检查物件、小物件、人物站位、出生点**放在哪里** | 关卡场景里按名字放的节点 | 同上 |
| 线索的文字、证据、连线 | 填表（1.3） | 只靠名字就能接上 |
| 小物件用哪个模型文件 | 填模型资产表（第 3 节） | 只靠名字就能接上 |
| 镜头的顺序、文字、动作、节奏 | 镜头表（1.1），由用户 + agent 维护 | 运镜与节奏优先交给 agent |

两边只靠**名字**对上：镜头表 `camera` 列写的机位名、可检查物件表的 `hs_` 编号、模型资产表的 `prop_` 编号，都必须是关卡场景里的节点名。

## 2. 关卡场景 `godot/levels/<房间id>.tscn`

一个房间一个场景，文件名就是房间登记表 `rooms.csv` 里的 id（如 `levels/darkroom.tscn`）。有这个文件，游戏就用它；没有，就暂时用灰盒（见第 4 节）。

在 Godot 里：新建场景 → 根节点选 `Node3D` → 搭房间 → 存到 `res://levels/`。改完不用填任何表；在游戏里按 F1 跳到对应镜头就能看到。

### 命名约定

| 节点名 | 节点类型 | 作用 |
| --- | --- | --- |
| `spawn` | `Marker3D` | 行走模式开始时玩家站的地方，朝 -z 是玩家面朝的方向 |
| `cam_<机位>` | `Camera3D` | 镜头模式的机位。位置、朝向、`fov`（焦距）都按这个相机来；在编辑器里勾选“预览”就能从机位看出去。镜头表 `camera` 列写 `<机位>`（不带 `cam_`） |
| `hs_<编号>` | `CSGBox3D` / `MeshInstance3D` / `Marker3D` | 可检查物件。方块或网格本身就是物件的样子，热区贴着它；空节点则显示一个默认大小的高亮方块。编号与可检查物件表一致 |
| `chr_<人名>` | `Marker3D` | 人物站位，人形面朝这个节点的 +z。人名与人物表一致；`chr_镜中人形` 是终局镜中没有脸的白色人形 |
| `prop_<编号>` | `CSGBox3D` | 小物件占位。方块的尺寸就是建模规格；模型资产表给了模型，游戏里就换成模型（第 3 节） |
| 其他任意名字 | 任意 | 都可以被镜头表的 `reveal(名字)` / `conceal(名字)` 显示或隐藏 |

其他规则：

- **单位是米。** 门高约 2.1 米，层高约 3 米。
- **碰撞**：用 CSG 方块时勾选 `Use Collision`；用网格时外面套一个 `StaticBody3D`。
- **开始时隐藏**：在编辑器里把节点设为不可见，由镜头表 `reveal(名字)` 让它出现（如第 0 章的尸体）。
- **渗漏变白**：L3 起房间里所有表面会换成白模网格。不该变白的（如镜面）加到 `no_leak` 组里（节点 → 分组）。
- **灯光**直接放在场景里。不要在关卡里放 `WorldEnvironment`，雾和环境光由程序统一控制。
- **同一画面只有一个人物**：一个关卡场景里只放一个 `chr_`（镜中人形除外），其他人先隐藏再用 `reveal` 轮流出现。

### 检查

运行内容检查（`检查内容.command`）后，`检查报告.md` 会列出：

- 镜头表用到但场景里没有的机位、物件、`reveal` 名字；
- 人物表里所在房间是这个房间、但场景里没有 `chr_` 的人；
- 场景里有、但可检查物件表或模型资产表还没登记的 `hs_`、`prop_`；
- **关卡场景与小物件规格**：已搭了哪些房间，以及每个 `prop_` 占位方块的尺寸（就是给美术的建模规格）。

## 3. 模型资产表 `godot/content/visual/props.csv`

**一行 = 一个小物件模型。** 关卡里的位置和大小由占位方块决定，这张表只决定“换成哪个模型”。

| 列 | 中文意思 | 怎么填 |
| --- | --- | --- |
| id | 编号 | 与关卡里的占位节点同名，`prop_` 开头，如 `prop_teacup` |
| name | 名称 | 茶杯 |
| model | 模型文件 | 如 `res://art/props/teacup.glb`；留空 = 还没交付，游戏里显示占位方块 |
| note | 备注 | — |

**给美术的规格**：模型尺寸以检查报告里“小物件规格”一节为准（宽 × 高 × 深，米）；**模型原点放在底面中心**，正面朝 +z。模型交到 `godot/art/props/`，填表即生效。模型不要带灯光。

## 3.5 房间状态表 `godot/content/space/room_states.csv`（10-15）

同一个房间在不同章节样子不同（门被撞坏、多一副餐具、墙上多一张画），用这张表决定**哪一镜打开哪一层**。空间本身仍在关卡场景里，表只靠层名接上。

| 列 | 写什么 |
| --- | --- |
| `room` | 房间 id（房间登记表里的） |
| `layer` | 层名。关卡场景里对应一个名为 `层·<层名>` 的节点：状态层是 `room_<id>__<层>.gltf` 的实例，开关是一组灯 / 发光件 |
| `kind` | `状态层`（多出或换掉物件，单独一份模型）或 `开关`（同一物件改属性：灯、火、窗帘、门锁） |
| `from` / `until` | 镜号：从 `from` 那一镜起打开，到 `until` 那一镜之前关上；留空 = 从头开 / 一直开 |
| `note` | 剧情依据 |

同一层可以写好几行（例如红灯在案发当晚亮、第 6 章冲洗时再亮）。人物与尸体、线索何时可查、白天黑夜不写在这里。校验工具会检查房间与镜号，并提醒关卡场景里缺的 `层·` 节点。游戏每播一镜就按这张表切换一次（`world/scene_host.gd` 的 `apply_room_states`）。

**热区也可以是不可见的 `Marker3D`**：物件已经在美术模型里时（庄园的房间模块），在物件位置放一个名为 `hs_<编号>` 的 `Marker3D`，在检查器的元数据里加 `size`（Vector3，米），就是热区大小。

## 4. 过渡：还没有关卡场景的房间

还没搭关卡场景的房间，仍按房间登记表的尺寸和房间布局表 `layout.csv` 生成灰盒，保证整条主线一直能自动通关。某个房间的关卡场景搭好后，布局表里这个房间的行就不再生效（检查报告会提醒删掉）。12 个房间都搭完后，房间布局表、房间登记表的尺寸列和灰盒代码一起删除。

布局表的格式（仅过渡期）：`type` 为 家具 / 可检查物件 / 机位 / 灯光 / 人物 / 出生点；家具的 y 是底部离地高度；`hidden` 填“是”则开始隐藏。人物表的 x, y, z 也只给灰盒用。

## 常见错误

- 节点名打错（`cam_Wide` 与镜头表的 `wide` 对不上）：检查报告会提示，游戏里会退回默认机位。
- 机位放在墙外，画面一片黑。
- 可检查物件被家具挡住，准星碰不到。
- 占位方块用了缩放（Scale）而不是尺寸（Size）：规格会读错。改大小请改 `Size`。
