# 1.3 线索与推理

负责：剧情 / 策划。三张表都在 `godot/content/story/`。

三张表的关系：玩家**检查物件**（可检查物件表）→ 得到**证据卡片**（证据表）→ 在证据板上把两张卡片**连起来**（连线规则表）。

## 证据表 `evidence.csv`

**一行 = 证据板上的一张卡片。**

| 列 | 中文意思 | 怎么填 |
| --- | --- | --- |
| id | 编号 | `ev_` 开头，如 `ev_key_tags` |
| name | 卡片标题 | 钥匙牌 |
| conclusion | 支撑哪个结论 | `F1`—`F3` 或 `C1`—`C3`，见《02-剧情设计》第 3 节；只是氛围的留空 |
| note | 卡片小字 | 卡片上显示的一句提示：打字机打的，e 偏高 |

## 可检查物件表 `hotspots.csv`

**一行 = 场景里一个能检查的东西。** 它在房间里的位置写在房间布局表里（类型“可检查物件”），这里写玩家检查后看到什么。

| 列 | 中文意思 | 怎么填 |
| --- | --- | --- |
| id | 编号 | `hs_` 开头，与房间布局表、美术模型里的物体名一致 |
| scene | 所在房间 | 房间编号 |
| label | 名称 | 玩家看向它时提示“检查：钥匙牌” |
| text | 检查后看到的描述 | 玩家读到的文字 |
| evidence | 得到的证据 | 证据表里的编号；只是氛围就留空 |
| note | 备注 | 如“可选”“双解读” |

## 连线规则表 `links.csv`

**一行 = 一对连起来算对的证据。** 同一组（group）可以有好几对正确答案。

| 列 | 中文意思 | 怎么填 |
| --- | --- | --- |
| group | 连线组 | 与镜头表 `link(...)` 括号里的名字一致：`c1` / `c2` / `c3` |
| a, b | 两张证据 | 证据表编号，顺序无所谓 |
| response | 连对后的回应 | 玩家连对后读到的文字（报纸来信、更正栏等） |
| note | 备注 | 写镜号（如 `N6-02`）时，这一行的回应会在那个镜头固定播放 |

## 设计规则

- **三线索规则**：每个结论在任何一条路径上都至少有三条线索，见《02》第 6 节线索审计。
- 找线索不卡关，难度放在“怎么解读”上。
- 所有描述不得违反事实锚点 F1—F3。

## 常见错误

- 可检查物件表里有，房间布局表里没放 → 玩家在房间里找不到它（检查报告会提示）。
- 证据编号拼错，连线永远连不对。
