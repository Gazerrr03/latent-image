# 房间模块 SOP：在庄园里建一个房间

更新：2026-10-16。基准案例：客房 + 前室（`16_room_guest.py`，用户验收通过）；复用验证：暗房（`17_room_darkroom.py`，多个可叠加的状态层、与温室共用侧门）、温室（`21_room_greenhouse.py`，与室外相连、植物卡片）；批量复用：门厅组、餐厅、客厅、照片档案室、艾瑞斯的房间（`24—28`，直角多边形房间一次做完饰面，见第 3 节）。

适用于大地图 `manor` 里的每个房间（温室、暗房、门厅……）。房间怎么划分、有哪些状态，以 [manor](manor.md)“房间划分与状态”为准；通用的关卡流程见[关卡开发规范](关卡开发规范.md)。

## 0. 三条原则

1. **一份空间，原位建模。** 房间直接建在 manor 坐标上（Blender x=东 X，y=北 N，z=标高），嵌回庄园、导进 Godot 都不需要对位。
2. **版本是状态层，不复制空间。** 同一房间在不同章节的样子，只把“真的变了的物件”放进状态子集合；墙、地板、固定家具只有一份。
3. **以墙的内表面为界分工。** 结构墙、洞口、楼板、天花、窗框与玻璃归 manor（`11`）；墙面饰面、线脚、门扇门套、窗台板与窗帘、壁炉、家具、物件归房间。

## 1. 输入盘点（开工前，约 10 分钟）

| 要什么 | 从哪来 | 够不够的标准 |
| --- | --- | --- |
| 外壳：净尺寸、门窗洞口、层高 | v1 尺寸表与设计坐标 json；洞口位置从平面 SVG 读（见下方命令） | 每个洞口有 u 范围与标高 |
| 陈设与氛围 | 旧设计包 `assets/2d/T-02x-<房间>/` 的透视图 | ≥ 3 张不同朝向，能看到 3 面墙以上 |
| 剧情必须有的物件 | 《03》第 1 节功能表、镜头表 `shots.csv` 与 `hotspots.csv` 里该房间的行 | 每个物件都落在一个具体位置 |
| 状态 | [manor](manor.md)“状态穷举” | 每个状态写清楚变了哪几样东西 |

读某个范围内的洞口（客房那次用的）：在 `assets/3d/manor/scripts/` 下用系统 Python `exec` 11 的“3. 读图纸”一节，再按 X、N 范围筛 `ops2`（二楼）或 `ops1`（一楼）。

**参考图与 v1 冲突时以 v1 为准**，并把冲突与处理写进 `manor.md`“已定的布置”（客房那次：窗外景色、菱格窗 → 推拉窗、壁炉跟着烟囱走、镜子移到前室）。

## 2. 定布置，先写文档再建模

在 `manor.md` 里写下：每件家具靠哪面墙、坐标大概多少、为什么；状态各变什么。需要用户拍板的（镜子放哪、工作台挡不挡百叶）先问。布置的检查点：

- 门扇开启扫过的范围不碰家具；通道宽 ≥ 0.6 m。
- 剧情物件能被看到（例如暗房内侧百叶不被工作台挡住）。
- 壁炉对着烟囱；书桌靠窗采光；床头靠实墙。

## 3. 写房间脚本 `assets/3d/manor/scripts/1x_room_<id>.py`

开头 `exec` 公用工具 `room_lib.py`，然后按这个顺序（照抄 `16_room_guest.py` 的结构）：

1. `room_collections(id, 名, [状态…])`：建 `ROOMS / 房间_<名> / {空间, 状态_…}`，重复执行会先清空。
2. `strip_manor(...)`：删掉 manor 里被房间接管的东西（客房：三扇窗的窗帘与窗帘盒；暗房：温室侧门的外门扇、百叶背板；温室：简化台架、手压泵、盆栽），同时在 `11` 的 `ROOM_OWNED` / `GH_BY_ROOM` 里登记，保证重建庄园时也不再生成。删除框的下沿要比 manor 部件的底面低一点（温室那次漏了泵座底面，留下 4 条缺面边）。
   **两个房间共用的东西先定归属再建**：例如暗房—温室侧门，门扇（带插销、原点在合页轴）归暗房，温室那一侧保留 manor 的石门套与门槛。写进 `manor.md`。
3. 墙：每面墙一个 `Wall(side, 内表面坐标, u0, u1)`；`wall_finish` 留洞口、分墙裙上下；`moulding` 沿内轮廓扫踢脚、墙裙压条、天花线脚，门洞处用 gaps 断开。10-16 起直接用 `finish_room(P, 轮廓, 洞口, …)`：给出墙内表面围成的直角多边形（逆时针，共线点可以把一面墙分段）和每条边上的洞口，饰面、踢脚、墙裙压条、天花线脚与门窗处的断口一次做完；楼梯井这类特殊墙用 `skip` / `bare` 排除后单独做。窗用 `window_dress`，烟囱墙用 `chimney_breast`。
4. 窗与门：窗台板、窗洞内侧贴面、窗套、窗帘；门洞 `lining` + 两侧 `architrave`；门扇 `door_leaf`（原点在合页轴，Godot 里直接转）。
5. 固定装修（壁炉、壁橱、工作台）→ 家具 → 小物件：每件一个物体，在局部坐标里建（正面朝 -y），`build(P, 名, 集合, 位置, 朝向角)` 放进房间。朝向：正面朝 +x 用 90°，朝 -x 用 -90°，朝 +y 用 180°。
6. 状态物件放进各自的状态集合（例：夹层抽屉推回去 / 拉开）。状态层可以叠加（第 6 章暗房 = 门撞坏 + 冲洗布置），陈列区里叠加的格子要把两层都实例进来；原位视图层只打开默认状态（暗房默认“门撞坏”，即调查日）。灯这类“开关”不做状态层，在关卡场景里做成一组灯（见第 7 节）。
7. 陈列区：每个状态一格（`show_instance` 空间 + 该状态），东侧 X 42 起往后排。
8. 审查相机 `rcam('房间审查·<名>·<视角>', …)`：至少一张与每张参考图同视角的，外加近景。
9. 结尾恢复控制台的 `C, D`。

**命名**：物体名 `<房间>·<物件>`，大件加 `-col`（Godot 生成碰撞）。**门扇也要有碰撞**（10-17）：已导出的门扇在 Godot 的导入设置里打开（`.gltf.import` 的 `_subresources` → `nodes` → `PATH:<节点名>`：`generate/physics = true`、`physics/shape_type = 2` 三角网格），manor 的 `门窗_oak / _olive / _paint / _glass / _iron` 同样处理；导入设置按节点名保存，重新导出不会丢。**能开的门**：名字以“门”结尾、不带括号说明的门扇，行走时走近按 E 开关（往离开玩家的一侧推开，推不开就换一边）；带“（锁着）”“（关着、插上）”“（撞开）”的开不了。所以门扇的原点必须在合页轴上、关着时末端贴着门洞，名字照这个规则写。新房间的门扇直接在 Blender 里命名带 `-col`。剧情物件名字写清楚，方便用户在 Godot 里对着摆 `hs_`。

**家具朝向**：局部坐标正面朝 -y。靠北墙的家具不转（0°），靠南墙 180°，靠西墙 90°，靠东墙 -90°。暗房那次把北墙工作台转了 180°，抽屉朝墙，体检才发现。

**公用件**：`room_props.py`（拉手、书、挂钟、油画、吊灯、篮子、地毯）；植物用 `room_lib.Cards`（4×4 图集卡片，材质 `clip=True` 导出成 glTF MASK）。放在地上的东西要放在地面完成面上（温室的石板面 `FS`，不是 manor 地坪）。

## 4. 后台迭代：渲染 → 对照 → 挑错（4—6 轮）

```bash
B=/Applications/Blender.app/Contents/MacOS/Blender; cd assets/3d/manor
$B -b manor.blend --python scripts/1x_room_<id>.py -- /tmp/room.blend          # 另存，不碰 manor.blend
$B -b /tmp/room.blend --python scripts/18_room_review.py -- <名> both          # 白天 / 夜晚
python3 scripts/19_room_compare.py <名>                                          # 参考 | 白天 | 夜晚
```

每轮按这张清单挑一两个最影响观感的问题修：

| 看什么 | 客房那次踩过的坑 |
| --- | --- |
| 整体色调与亮度 | 天光偏蓝。白平衡数值是“当作白色的色温”，要偏暖得调高（7600），不是调低 |
| 材质颜色对不对 | **带贴图的材质会忽略底色**：大衣、外套、座面、柳条都变成了贴图的芥末黄。换色的布料只用法线贴图 + 底色。**底色是线性值，不是 sRGB**：深色木头要写 0.07 左右（≈ sRGB 0.3），按 sRGB 写的 0.30 会渲成浅黄褐色（暗房第一轮的工作台、凳子、三脚架都发白） |
| 木纹、墙面是否“像橘皮” | 法线强度过高；家具木纹 0.12、墙面 0.15 就够 |
| 构图是否被挡 | 门扇、开着的衣柜门挡镜头：挪相机或改开门角度 |
| 物件是否像 | 打字机第一版是实心盒子；改成底板 + 侧框 + 扇形字锤才像 |
| 状态是否叠在一起 | 原位视图层只开第一个状态，其余状态只在陈列区看 |
| 夜景灯是否被挡 | 审查点光不能放进灯泡球体或封闭灯罩里 |
| 灯光强度 | 小房间（3.5 m）里 90 W 的点光会把深色墙照成灰白；暗房白天 22 W 就够。红光用 AgX 时偏橙，要压低强度才保得住深红 |
| 剧情物件看不看得清 | 全黑相纸泡在深色药液里看不见：加一圈白边、浮在液面上 |
| 植物密度 | 第一轮总是太稀：盆栽叶片卡片 20 张以上、花架下层和矮墙上都要有东西 |
| 单面件是否消失 | 墙面饰面、布、纸是单面，不能和要重算法线的件共用一个部件；用别名材质键（`wallf`、`linenf`） |

**A 组五个房间（10-16）补充的坑**：

| 现象 | 原因与改法 |
| --- | --- |
| 体检报出 9.5 m² 共面重叠，大半在楼梯井墙上 | 只做上部灰泥的墙段把“墙裙线”设在地面以下，`wall_finish` 照样多切了一格，与一楼那段重叠；墙裙线不在墙高范围内时不切 |
| 铸铁炉芯整片自相重叠 | 拱形开口的“U”形凹多边形三角化出错（导进 Godot 一样会错）；凹多边形拆成凸块再拉伸 |
| 家具腿穿过地毯 | 站在地毯上的家具放在地毯面上（+1.15 cm）；地毯只铺在真正放东西的范围 |
| 落地窗帘与沙发、壁炉、书柜打架 | 落地窗帘占墙前约 0.15 m；靠窗的家具离墙至少 0.45 m，或改用短帘 |
| 状态层里的东西互相压着（餐具、汤盆、烛台） | 排布体检只查“空间”集合；状态层要按“空间 + 该层”逐个检查，桌面上的东西先排好格位 |
| 平日摆设与状态层冲突（圆桌花瓶 vs 降灵会蜡烛） | 会被状态层占用的位置，空间里不放东西 |
| 帘杆托架、灯座嵌进天花 / 墙面 4 mm | 贴墙、贴天花的件离饰面 ≥ 1 mm，线脚顶面低于天花 |
| 同一件家具里几块板端面平齐（椅子横档与腿、壁柱与柱础、书柜门框四根料） | 端面错开 2—5 mm，或让一块插进另一块里 |
| 从暗房侧门走进温室掉下去（10-17） | 关卡场景只放了自己的房间模块，邻屋的地面不在场景里。玩家走得进去的邻屋（门开着、或门洞没有门扇）要在关卡场景里作为 `邻·<房间>` 实例进来（暗房关卡加了 `邻·温室`）；走不进去的，门扇要有碰撞 |
| 门外的楼梯不见了、走廊是没饰面的白壳（10-17） | 主楼梯 10-16 从 manor 挪进门厅模块，没带门厅模块的关卡门外就空了。某个模块接管了 manor 的部件（`ROOM_OWNED` / `STAIR_BY_ROOM`），就把所有看得见那块地方的关卡场景都加上 `邻·<房间>`；`grep -L room_hall godot/levels/*.tscn` 可以查漏 |
| 楼梯只能下不能上（10-17） | 胶囊体的圆底爬不上竖直的踢面。已在 `player.gd` 用脚下分离射线解决（能直接迈上 0.32 m 以内的台阶），楼梯不需要做成斜坡碰撞 |
| 温室里走着走着掉下去、能穿过玻璃（10-16） | manor 外壳里温室的地面、矮墙、玻璃不带 `-col`；能走进去的空间都要确认地面与墙有碰撞，没有就在房间模块里加 `<房间>·碰撞-colonly`（Blender 里设为线框、不渲染），并用 Godot 射线测一遍 |
| Godot 里的人物灰盒背对镜头 | 人形朝站位节点的 +z（设计坐标里 yaw 0 朝南），与 spawn 的朝向约定相反 |

## 5. 几何体检

```bash
cp review/geometry_check.json /tmp/geometry_check_manor.json
$B -b /tmp/room.blend --python scripts/09_check_geometry.py
cp /tmp/geometry_check_manor.json review/geometry_check.json                     # 还原庄园的正式结果
```

目标：房间相关共面重叠合计 < 0.01 m²，且房间与 manor 之间为 0。房间单面件不查缺面；同一房间不同状态之间的重叠不算。常见原因：

- 贴脸板的立边与顶板在角上相交 → 立边截到顶板下沿。
- 门窗套内沿与窗洞贴面同一平面 → 贴面错开 2 mm。
- 线脚底面与柜体底面同高 → 线脚截面向下嵌 6 mm。
- 中立板伸进背板、两块脚料在角上重叠、门扇中梃穿过中冒头 → 让它们首尾相接，不交叉。
- 竖板墙裙的板与板、板与门套在角上相交 → 板子离墙角 2 cm，底面抬高 4 mm。
- 叶片卡片全都平行 → 每片随机倾斜几度。
- 体检把平面按 3 位小数分组，门扇转过一个角度时，1 mm 之隔的两个平行面可能被算成同一平面（假阳性）；即便如此，平行面之间至少留 2 mm。

查不出是哪对面时，用 `scripts/09b_overlap_detail.py -- "<物体名>"` 逐对打印重叠三角形的坐标。

## 5.5 排布体检（只看几何，不看参考图）

渲染对照只能看出“像不像”，看不出东西是不是穿进了墙、悬在空中、挤在一起。每个房间做完都要跑一遍：

```bash
$B -b /tmp/room.blend --python scripts/23_layout_audit.py -- <名>      # 输出 review/rooms/<名>/排布体检.json 与 排布俯视.png
```

它把房间里每个物体拆成相连的块，检查：穿进固定结构（manor 的墙、矮墙、铸铁框、玻璃）、物件之间互相穿插、植物卡片穿出墙或玻璃、超出房间范围、悬空。目标是前四项为 0；“悬空”里有不少是假阳性（贴墙的苔斑、侧面连着的管子、盆底正好落在木条缝上），要逐类看一遍，只修真的。再看平涂俯视图：**先留出通道（门与门之间的路线），其余东西靠墙、成行，不在地上随手散放**。

温室那次（10-16，用户指出“排布杂乱”）查出的真问题：矮墙上的一排盆整排穿过玻璃与铸铁框（玻璃就立在矮墙中线上，没有台面）；300 多张叶片卡片穿出玻璃或扎进墙；侧门两侧的大盆互相挤、压在门槛石上；花架木条底下没有托梁；盆是封口的、盆土被封在里面；开口的木箱上叠空盆；落地盆散在通道里。

## 7. 导出与进 Godot

```bash
$B -b manor.blend --python scripts/03_export_glb.py            # 庄园（被接管的窗帘已删）
$B -b manor.blend --python scripts/20_room_export.py -- <名>   # room_<id>.gltf + room_<id>__<状态>.gltf
```

- `godot/levels/manor.tscn` 的 `结构/房间` 下放：空间一个实例、默认状态一个实例，都不加偏移。
- **关卡场景 `godot/levels/<房间id>.tscn`**（10-15 起，接入玩法）：引用庄园外壳 + 房间空间 + 各状态层（节点名 `层·<层名>`）；开关做成 `层·<层名>` 下的一组灯；`spawn`、`cam_<机位>`（镜头表 camera 列用到的每一个）、`hs_<编号>`（不可见 `Marker3D` + `size` 元数据）、`chr_<人名>`、`chr_尸体` 等接口节点。初稿可用 `tools/levels/gen_manor_room_levels.py` 生成，之后以编辑器里的修改为准（重跑会覆盖）。用 `--capture=<镜号>` 截游戏里的画面验收。
- `capture_level.gd` 的 `EXTRA` 加这个房间的视角，`--only=<名>` 截图；再跑内容校验与两种讲法的自动通关。
