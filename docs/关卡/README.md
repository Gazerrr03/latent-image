# 关卡需求

更新日期：2026-10-17

**一个关卡一篇文档。** 文件名就是关卡 id，与关卡场景 `godot/levels/<id>.tscn` 同名。每篇写清楚：这个关卡要承担什么、硬性约束、空间布局、物件清单、留给程序的接口、从 Blender 到 Godot 的做法、待定事项。新文档从 [_模板](_模板.md) 复制。

**效果预览图按关卡浏览**：见 [预览/](预览/README.md)（由 `python3 tools/art/level_previews.py` 生成，新增图片后重新运行）。

**3D 关卡与房间的总流程**（空间预期 → 预览图 → Blender 建模 → Godot 试玩，含防穿模的建模规范）：先读 [3D 建模工作流 SOP](3D建模工作流SOP.md)（10-19）。

**怎么开发一个关卡、各阶段产物放在哪里**：见 [关卡开发规范](关卡开发规范.md)（以 `train` 为基准案例）。庄园里的房间按 [房间模块 SOP](房间模块SOP.md)（以客房为基准案例）；未建房间还缺的效果图见 [补图需求-v3](补图需求-v3.md)。

空间与镜头构图由用户在 Godot（必要时结合 Blender）里把控，文档写的是**需求**，不是最终设计；搭的过程中改了尺寸，回到文档里同步。上游依据：剧情《02》，玩法《01》，空间需求《03》（大地图第 1 节、可进入线索与小关卡第 2 节）。
