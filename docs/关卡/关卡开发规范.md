# 关卡开发规范

更新日期：2026-10-14

本文规定**一个关卡怎么从需求做到能玩**，以及做的过程中每一样东西放在哪里、由谁管、进不进 git。基准案例是火车车厢 [`train`](train.md)：它是第一个按这套流程完整走通的关卡，凡是本文没写到的细节，照 train 的做法。

适用对象：用户和 agent（代码与关卡场景只由这两方修改）；队友只交设计包、模型、图片、声音等文件，规则见根目录 `CONTRIBUTING.md`。

相关文档：每个关卡的需求写在 [`docs/关卡/<id>.md`](README.md)；节点命名的细则见 [填表说明 1.4](../填表说明/1.4-空间与地图.md)；表格列含义见《06》第 2 节；素材生成与登记见 [`assets/README.md`](../../assets/README.md)。

---

## 1. 一个关卡由什么组成

一个关卡分**六层**，自上而下逐层落地。上一层是下一层的依据；运行时只读第 4、5、6 层。

```
① 需求      docs/关卡/<id>.md              这个关卡要承担什么、约束、空间与物件、接口
     ↓
② 设计包    assets/2d/<T-编号>-<名称>/      平面图、机位透视、物件清单、坐标交接 json
     ↓
③ 3D 源     assets/3d/<id>/                 .blend 源文件、建模脚本、烘焙、检查截图（本机为主）
     ↓ 导出 glb
④ 运行资产  godot/art/levels/<id>/          .glb、材质 .tres、贴图
     ↓ 实例化
⑤ 关卡场景  godot/levels/<id>.tscn (+ .gd)  空间的唯一依据：结构 / 灯光 / 接口
     ↑ 按名字接上
⑥ 内容表    godot/content/**/*.csv          镜头、文字、动作、声音、线索、小物件模型
```

**两条铁律：**

1. **空间不进表。** 尺寸、墙、家具、灯、机位、物件摆放，只存在于第 ⑤ 层的 `.tscn` 里，由人在 Godot 编辑器里搭和调。不要用代码或表格生成、改写关卡空间。
2. **内容不进代码。** 文字、镜头顺序、动作、声音、线索都在第 ⑥ 层的表里。第 ⑤ 层和第 ⑥ 层之间**只靠节点名字**接上（`cam_seat` ↔ 镜头表 `camera=seat`）。

## 2. 文件放在哪里

### 2.1 总表

| 层 | 位置 | 内容 | 进 git | 性质 |
| --- | --- | --- | --- | --- |
| ① 需求 | `docs/关卡/<id>.md` | 关卡需求文档（从 [_模板](_模板.md) 复制） | 是 | 最终产物（持续更新） |
| ① 索引 | `docs/关卡/README.md` | 全部关卡一览：id、类型、章节、优先级、状态 | 是 | 最终产物 |
| ① 纵切面 | `godot/content/levels.csv` | 章节 → 节点、目标、涉及房间、状态 | 是 | 最终产物 |
| ① 任务卡 | `docs/任务/T-xxx-<名称>.md` | 派给队友的设计包或模型任务（`/task-card`） | 是 | 中间产物 |
| ② 设计包 | `assets/2d/<T-编号>-<名称>/` | 平面图、透视图、物件清单、`*_坐标交接.json`、`prompts/`、`来源.md` | 是（`drafts/` 除外） | 中间产物 |
| ③ 源文件 | `assets/3d/<id>/<id>.blend` | 可编辑模型 | **否**（只在本机） | 中间产物 |
| ③ 脚本 | `assets/3d/<id>/scripts/NN_*.py` | 搭建、渲染、导出、烘焙的 Blender 脚本，按顺序编号 | 是 | 中间产物（可复现的依据） |
| ③ 烘焙 | `assets/3d/<id>/baked/` | 烘焙布光源、烘焙结果 `.blend`、`bake-manifest.json` | `.blend` 否，manifest 是 | 中间产物 |
| ③ 参考 | `assets/3d/<id>/references/` | 氛围参考图 | 是 | 中间产物 |
| ③ 贴图源 | `assets/3d/<id>/textures/` | 贴图原图与生成提示词 | 是 | 中间产物 |
| ③ 检查 | `assets/3d/<id>/review/` | 构图截图、`cameras.json`、导入日志、验证 json | 是 | 中间产物（验收证据） |
| ③ 备份 | `assets/3d/<id>/backups/` | 每次大改前的备份 | **否** | 中间产物 |
| ③ 说明 | `assets/3d/<id>/README.md` | 这个目录里什么是什么 | 是 | 中间产物 |
| ④ 模型 | `godot/art/levels/<id>/<id>.glb`（或 `<id>-baked.glb`） | 游戏用模型，**不含相机与灯光** | 是 | **最终产物** |
| ④ 材质 | `godot/art/levels/<id>/*.tres` | 覆盖材质（烘焙材质、发光、动态贴图） | 是 | **最终产物** |
| ④ 贴图 | `godot/art/levels/<id>/textures/` | 运行时用到的贴图 | 是 | **最终产物** |
| ⑤ 场景 | `godot/levels/<id>.tscn` | 关卡场景 | 是 | **最终产物** |
| ⑤ 脚本 | `godot/levels/<id>_<用途>.gd` | 仅这个关卡用的行为（如 `train_window.gd`） | 是 | **最终产物** |
| ⑥ 内容表 | `godot/content/story/shots.csv` 等 | 见第 5 节 | 是 | **最终产物** |
| ⑥ 小物件 | `godot/art/props/<名称>.glb` | 可单独替换的小物件模型 | 是 | **最终产物** |
| ⑥ 影像 | `godot/art/footage/` | 叠印、合影、片头等图片与视频 | 是 | **最终产物** |
| 登记 | `assets/登记表.csv` | 每个素材一行：版本、文件、提示词、工具、游戏路径 | 是 | 记录 |
| 记录 | `docs/08-决策与更新记录.md` | 每次设计决定或交付记一笔 | 是 | 记录 |

**判断口诀：** 游戏运行时读得到的，放 `godot/`；做出它的过程，放 `assets/`；为什么要这样做，放 `docs/`。

### 2.2 id 与命名

- **关卡 id**：英文小写加下划线，如 `train`、`manor`、`ded_photo`。演绎关卡以 `ded_` 开头。下面这些地方统一用同一个 id：需求文档名、`.tscn` 名、`assets/3d/<id>/`、`godot/art/levels/<id>/`、镜头表的 `scene` 列。
- **设计包目录**按任务编号命名（`assets/2d/T-035-火车车厢/`），因为它是派出去的任务；3D 目录与运行资产**按关卡 id 命名**，因为一个关卡可能经过多张任务卡。
- `assets/README.md` 第 2 节旧写法是 `3d/<任务编号-名称>/{source,export,preview}`。关卡的 3D 目录以本节为准（train 的结构），人物、片头等非关卡素材仍按 `assets/README.md`。
- 运行资产里不要留无引用的旧版本。被替换的文件移到 `assets/3d/<id>/backups/`（本机），不要留在 `godot/` 里。

## 3. 开发流程

每个阶段都有交付物和一道“过门”检查，过了才进入下一阶段。任何阶段都必须能由**用户 + agent 独立完成**；派给队友的部分，要写明兜底做法。

### 阶段 0：立项

- 在 `docs/关卡/README.md` 的一览表里登记 id、类型（当下 / 演绎 / 外面）、章节、优先级。
- 在 `levels.csv` 的对应章节里写进这个关卡。

**过门**：id 确定，且后续不再改。

### 阶段 1：需求文档 `docs/关卡/<id>.md`

从 [_模板](_模板.md) 复制，按顺序写：

1. **要承担什么**：剧情事件，以及用到的**镜号、机位名、画面**，列成表。机位名就是以后 `cam_<机位>` 的名字。
2. **硬性约束**：从《02》固定事实 T1—T5、美术共同基准里挑出对这个关卡起作用的几条，再加上关卡自己的约束（train 的例子：不放镜子、不出现可读文字、红色只给暗房、窗外风景每隔一段重复一遍）。
3. **交互范围**：固定机位过场、可走动，还是演绎关卡？这条决定了建模范围和是否需要碰撞（train 定为固定坐姿，所以只建镜头看得到的部分）。**必须先跟用户确认。**
4. **空间布局**：坐标约定（原点在地面中心，单位米，x 向右，y 向上，-z 是前墙）、平面示意、尺寸表。只写“建议”，并标出唯一不能动的要求（train：`seat` 机位要能看到整扇车窗）。
5. **物件清单**：尺寸、材质、说明；标出剧情主角物件，以及以后要复用的空位（train 的对面座位要留空，给演绎关卡 L1-b 用）。
6. **留给程序的东西**：接口节点名，以及需要单独命名的网格（如 `窗外画面`）。
7. **待定事项**。

**过门**：用户确认交互范围和镜头表；文档里出现的机位名和物件编号，以后不再随意改。

### 阶段 2：设计包（可派给队友）

放在 `assets/2d/<T-编号>-<名称>/`：平面图、每个机位一张透视图、物件清单、坐标交接 json（机位位置、朝向、焦距，物件位置）。派任务用 `/task-card`，任务卡存 `docs/任务/`。

**兜底**：agent 用 PIL 或 imagegen 按需求文档直接出图（train 的设计包就是程序渲染的）。

**过门**：透视图里，每个镜头的画面都能对上需求文档第 1 节。

### 阶段 3：Blender 建模 `assets/3d/<id>/`

> 庄园大地图里的房间（客房、暗房、温室……）不单独建 `<id>.blend`，而是原位建在 `manor.blend` 里、版本做成状态层，流程见 [房间模块 SOP](房间模块SOP.md)。下面的约定适用于独立关卡（火车、尾声、线索小关卡）。

- 源文件 `<id>.blend` 里分两个集合：**`<ID>_MODEL`**（要导出的内容）和 **`REVIEW_ONLY`**（构图检查用的参考相机 `REF_cam_<机位>` 和检查灯，不导出）。
- 每一步都写成 `scripts/NN_<动作>.py` 并保存，保证可以复现。
- 坐标换算：Blender 的 +Z 是 Godot 的 +y，Blender 的 -Y 是 Godot 的 +z。所以在 Blender 里**前墙放在 +Y 一侧**，原点放在地面中心，1 单位 = 1 米。
- 材质逐个命名（漆木、黄铜、丝绒……）。渗漏效果的白模由程序统一替换，只做正常版本。
- 需要动态画面的面单独做一个网格并命名，UV 铺满 0—1（train 的 `窗外画面`）。
- 想单独替换的小物件不放进整体模型，在 Godot 里用 `prop_<编号>` 占位（见第 4 节）。
- 只在可走动关卡里给地面、墙、家具的网格名加 `-col` 后缀，导入时会自动生成碰撞。
- 每轮修改后，用参考相机渲染检查图，存进 `review/`。

**光照二选一**（在需求文档里写明）：

| 做法 | 适用 | 注意 |
| --- | --- | --- |
| Godot 实时光（`灯光` 分组） | 可走动、光会变化、需要快速迭代 | 不放 `WorldEnvironment`，环境光由程序统一控制 |
| Blender 烘焙（train 用的） | 固定机位、对氛围要求高 | 布光源放 `baked/`。改了家具或布光必须**重新烘焙**，排期时要算进去。光照是静态的，没有动态阴影和随视角变化的高光 |

**过门**：参考相机渲染出来的检查图，用户看过并同意。

### 阶段 4：导出进 Godot

- 导出到 `godot/art/levels/<id>/<id>.glb`，**不勾选相机和灯光**。
- 覆盖材质存成 `.tres`，和 glb 放在同一个目录。
- 在 `assets/登记表.csv` 登记一行（`game_path` 填 glb 路径，`note` 写明以哪个 `.blend` 为准）。

**过门**：Godot 导入时没有报错，`.import` 文件已生成。

### 阶段 5：搭关卡场景 `godot/levels/<id>.tscn`

结构固定，见第 4 节。灰盒阶段可以先用 CSG 方块搭；模型到位后，把 glb 拖到 `结构/` 下，灰盒删掉或关掉，`接口/` 和 `灯光/` 保留。首次替换前，把旧场景备份到 `assets/3d/<id>/backups/`。

**过门**：在编辑器里逐个预览 `cam_*` 相机，构图符合需求文档。

### 阶段 6：接内容表

写镜头表各行，补齐线索、声音、小物件模型（第 5 节）。

**过门**：第 6 节的三条验证命令全部通过。

### 阶段 7：验收与记录

- 用 `--capture=<镜号>` 截出每个镜头，用户验收。
- 回写需求文档：状态、实际做法、和需求不一致的地方、还没做完的事。
- 更新 `docs/关卡/README.md` 的状态，在 `docs/08` 记一笔，在登记表里把状态从“候选”改为“定稿”。

## 4. 关卡场景规范

### 4.1 结构

```
<id>  (Node3D，可挂 <id>_<用途>.gd)
├── 结构/      模型实例、CSG 灰盒、碰撞体
├── 灯光/      OmniLight3D / SpotLight3D 等；烘焙关卡可以保留零强度的节点
└── 接口/      程序靠名字找的节点
    ├── spawn
    ├── cam_<机位> …
    ├── hs_<编号> …
    ├── chr_<人名> …
    └── prop_<编号> …
```

`scene_host.gd` 是**按名字前缀扫描整个场景**的，所以接口节点放在别的分组下也能被找到。但统一放在 `接口/` 下，方便查看和检查。

### 4.2 接口节点

| 节点名 | 类型 | 规则 |
| --- | --- | --- |
| `spawn` | `Marker3D` | 行走开始的位置，面朝 -z。纯过场的关卡也要放一个 |
| `cam_<机位>` | `Camera3D` | 位置、朝向、`fov`、`near` 会传给运行相机；相机自带的 `Environment` 也会生效（train 用它控制环境亮度）。机位名用英文小写，跟镜头表 `camera` 列对应（不带 `cam_`） |
| `hs_<编号>` | 网格 / CSG / `Marker3D` | 可检查物件。编号与可检查物件表一致 |
| `chr_<人名>` | `Marker3D` | 人物站位，人物面朝 +z。一个画面里只有一个人物，其他人先隐藏，再用 `reveal` 轮流出现 |
| `prop_<编号>` | `CSGBox3D` | 小物件占位。方块的尺寸就是给美术的建模规格 |
| 其他名字 | 任意 | 都可以用 `reveal(名字)` 或 `conceal(名字)` 控制显示和隐藏；开始时隐藏的节点，在编辑器里设为不可见 |

### 4.3 其他规则

- **不受渗漏效果影响的东西**（窗景、自发光的灯罩、镜面）加入 `no_leak` 分组。
- **不放 `WorldEnvironment`。** 某个机位需要特别的环境时，用这个 `Camera3D` 自己的 `environment`。
- **关卡专用行为**写成 `godot/levels/<id>_<用途>.gd`，挂在根节点上，通过 `Director.shot_started` 信号响应镜头。脚本里**不写剧情文字**，只写时长这类可调的 `@export` 参数（如 `train_window.gd` 的 `travel_seconds`）。如果要在编辑器里预览效果，加 `@tool`，并在 `Engine.is_editor_hint()` 分支里关掉运行逻辑。
- **不在 `core/` 代码里判断某个关卡 id。** 如果某种行为不止一个关卡要用，就把它做成表格里的一列或一个动作（新增动作的流程见《06》2.2）。现在的例外见第 8 节。

## 5. 内容表怎么接

| 表 | 关卡用到的部分 | train 的例子 |
| --- | --- | --- |
| `story/shots.csv` | 每个镜头一行：`scene=<id>`、`camera=<机位>`、`mode`（`camera` 固定机位 / 可走动模式）、`sound`、`text`、`actions`、`next` | C0-01—C0-03，`mode=camera` |
| `story/hotspots.csv` | `hs_` 编号对应的检查文字 | 不需要（过场） |
| `story/evidence.csv` | 镜头里用 `collect(...)` 收集的证据 | `ev_letter_p1` |
| `audio/sounds.csv` | 镜头 `sound` 列用到的声音；`file` 列为空时程序静默跳过，但检查报告会列出来 | `train_rattle`（文件待做） |
| `visual/props.csv` | `prop_` 编号 → 小物件模型路径 | 不需要 |
| `visual/footage.csv`、`fx.csv` | 叠在关卡上播放的影像和滤镜 | 片头 `footage(片头_警告)` |
| `space/rooms.csv`、`layout.csv` | **只给还没有关卡场景的房间搭灰盒用**。有了 `.tscn` 后，`layout.csv` 里对应的行要删掉。所有关卡都搭完后，这两张表整体删除 | 还剩 `train` 一行，留待统一删除 |

`actions` 列只能用 `core/actions.gd` 里的白名单。每个 `.csv` 旁边都要有 `importer="keep"` 的 `.csv.import`。

## 6. 验证

每次改动关卡后都要跑：

```bash
godot --headless --path godot --script res://tools/validate_content.gd   # 表与场景名字对得上；报告：检查报告.md
godot --headless --path godot -- --autoplay                               # 两种讲法都要过
godot --headless --path godot -- --autoplay --view=取代
godot --path godot --resolution 1280x720 -- --capture=<镜号> --wait=4 --out=/tmp/x.png   # 逐镜截图
```

检查报告会列出：镜头表用到了、但场景里没有的机位、物件和 `reveal` 名字；场景里有、但表里没登记的 `hs_` 和 `prop_`；每个 `prop_` 的尺寸规格。

在游戏里按 F1 可以跳到指定镜号，F5 运行完整工程。F6 只运行当前场景，不会跑分镜和字幕。

## 7. 记录与同步

| 发生了什么 | 同步到哪里 |
| --- | --- |
| 需求、范围、交互方式变了 | `docs/关卡/<id>.md` + `docs/08` |
| 关卡状态变了 | `docs/关卡/README.md` 一览表 + `levels.csv` |
| 新生成或更换了素材 | `assets/登记表.csv` |
| 新增了动作、表格列、通用行为 | `core/actions.gd`、`director.gd`、《06》2.2 |
| 命名规则变了 | 本文 + 填表说明 1.4 + `CLAUDE.md` |

需求文档末尾保留“交付记录”一节，按日期写：做了什么、**没做什么**、验证到了哪一步。没验证过的不写成“已完成”。

## 8. 已知例外与待办
