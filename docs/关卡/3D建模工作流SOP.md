## 0. 总览

```
A 空间预期        docs/关卡/<id>.md：要承担什么、交互范围、尺寸、物件、状态、机位
   ↓ 过门：用户确认交互范围与尺寸
B 预览图          assets/2d/<T-编号>-<名称>/：平面布置图 →（立面 / 剖面）→ 构图底图 → 人视效果图
   ↓ 过门：用户看过平面与效果图；平面与真实尺寸对得上
C Blender 建模    脚本化、后台迭代：渲染 → 和效果图同视角对照 → 挑错 → 改
   ↓ 过门：几何体检、排布体检达标（第 5 节）；对照图用户看过
D 在用户的 Blender 里执行并保存
   ↓ 过门：用户的 Blender 窗口里看得到、已保存、版本记录追加一行

   ↓ 过门：导入无报错；Godot 里的模型版本与 .blend 一致

   ↓

```

## 1. 做事方式（每个阶段都适用）

1. **先定目标和验收，再动手。** 用户给的往往是“非常精细”“独游精品水准”这类目标，agent 要自己把它拆成能检查的条目（尺寸、对照图、体检数字、截图），写进需求文档或任务书，然后用 goal 推进。
2. **缺陷要量化，降到 0。** “有没有穿模”不靠肉眼回答，靠第 5.6 节的体检脚本给出面积和条数。
3. **每一步写成脚本。** Blender 里的每次搭建、渲染、导出都是 `scripts/NN_<动作>.py`，可以重跑、可以复查。不在 GUI 里手点出不可复现的结果。
4. **后台迭代，GUI 收尾。** 迭代用 `blender -b`；做完必须在用户自己的 Blender 窗口里执行并保存（用户 10-15：“不要只是在后台”）。
5. **真实优先于还原。** 效果图是方向，不是尺寸来源。房间放不下就改设计、重出图，**不为了对上效果图把家具缩小**（用户 10-18，客厅）。
6. **Godot 里跑的必须是最新模型。** 每次导出后在 Godot 里看一眼改过的地方，不能出现“改了之后楼梯没了”这种版本倒退（10-17）。

## 2. 阶段 A：空间预期

写 `docs/关卡/<id>.md`（从 [_模板](_模板.md) 复制；庄园里的房间写进 [manor](manor.md) 对应小节），至少回答：

| 要定的事 | 为什么 | 例子 |
| --- | --- | --- |
| 承担的剧情事件、镜号、机位名 | 机位名以后就是 `cam_<机位>` 和效果图的视角 | 回廊：六层，每层“多出来的一件东西” |
| **交互范围**：固定机位 / 可走动 / 演绎 | 决定建模范围和要不要碰撞。**必须先问用户** | train 是固定坐姿，只建镜头看得到的部分 |
| 真实尺寸与坐标 | 预览图和建模都以它为准 | 庄园房间以 T-039 v1 平面与 `manor_设计坐标-v1.json` 为准 |
| 物件清单（剧情物件标出来） | 每件都要在图上和模型里落在具体位置 | 暗房的显影盘、内侧百叶 |
| 状态（不同章节的样子） | 决定状态层怎么拆 | 暗房：门完好 / 门撞坏 / 冲洗布置 |
| 硬性约束 | 防止预览图和模型越界 | 不画人、不画可读文字、红色只给暗房、不放镜子 |
| 走 manor 还是独立关卡 | 决定阶段 C 走哪条路（第 4 节） | 回廊是独立关卡，但做法照房间模块 |

**先查资料够不够**（用户 10-16）：已有的效果图、平面能不能撑起建模？不够就进阶段 B 补图；够了直接进 C。

## 3. 阶段 B：预览图（设计包）

### 3.1 出哪些图（按需要选）

| 图 | 什么时候要 | 怎么出 | 例子 |
| --- | --- | --- | --- |
| **平面布置图** | **每次都要** | 脚本画（SVG → PDF / PNG），1:50，0.5 m 网格，标尺寸、门窗洞口、家具占地、门的开启扇形 | `build_t041_package.py`、`build_t042_checkpoint.py` |
| **人视效果图** | **每次都要**，每个机位一张；同一机位的不同状态各一张 | Codex 生图，用构图底图锁比例（3.2） | T-041 十张、T-043 八张 |
| 构图底图 | 房间小、生图容易画大时（基本都要） | Blender 白模按平面摆好，从每个机位渲一张 | `render_t042_reference.py`、`seance_构图底图_east.png` |
| 立面图 | 一面墙上东西多、高度关系要紧（壁炉墙、书柜墙、窗与墙裙） | 脚本画 | — |
| 剖面图 | 有高差、楼梯、层高要紧，或是整栋建筑 | 脚本画 | `manor_剖面.svg` |
| 鸟瞰 / 外景人视 | 整栋建筑、室外 | Codex 生图 | T-039 `manor_鸟瞰_后`、`manor_人视角_1—3` |
| 近景 | 剧情物件要看清 | Codex 生图 | `corridor_gramophone-v1` |
| 物件清单、坐标交接 json | 每次都要 | 和平面图同一份数据生成 | `seance_坐标与检查-v4.json` |

### 3.2 顺序：先图纸，再底图，再生图

生图模型默认会把房间画成“豪宅大厅”（客厅 v3 两张因比例失真作废）。所以按这个顺序，**不跳步**：

1. **平面布置图**：从需求文档的尺寸与家具表直接用脚本画，画的同时算布置检查（门的开启扇形里不放家具、门前留 1.0 m、通道 ≥ 0.6 m、家具占地互不重叠，冲突处标红）。**草稿检查点：先给用户看平面比例，确认后再出效果图。**
2. **构图底图**：在 Blender 里按平面用方块（或已有的公用件）摆出家具，放好每个机位的相机（眼高 1.55 m，坐姿 1.20 m），渲白模图。
3. **效果图**：提示词 = `write_v3_room_prompts.py` 的 `HEAD + STYLE`（风格锁定）+ **比例锁**（房间净尺寸、层高、门窗数量、机位到主要物件的距离、镜头焦距、竖线竖直）+ **家具锁**（只有哪些家具、明确写出“没有什么”）+ 这一张的画面描述。参考图给两张：构图底图（管构图）和一张已有同风格的图（只管画风）。
4. **逐张核对**：对照“构图核对”表（主要物件在画面里的横向位置，允许 ±8%）和“画面里必须有”。不合格的**单张定向重出**，写清哪里错（“壁炉太小，房间画大了”），不整组重来；后一轮用上一轮的图作编辑目标。

### 3.3 常见偏差与处理

| 偏差 | 处理 |
| --- | --- |
| 房间画大、家具画小 | 加比例锁和构图底图；仍不行就局部编辑 |
| 生图和平面冲突（壁炉画成平贴墙、门合页画反） | **以平面为准**，建模按平面改正，把冲突写进需求文档 |
| 同一机位的几层（状态）构图不一致 | 底图同一台相机；验收清单写明“同一构图，只有光和那件东西不同” |
| 地毯、植物等铺张过大 | 效果图里标出，不作为尺寸依据 |
| 真实尺寸根本放不下需求里的东西 | 回到阶段 A 改需求（客厅：圆桌组和沙发组二选一），重出平面与效果图 |
| 出现人、可读文字、镜面反射人影、多余的红 | 按硬性约束重出 |

### 3.4 存放与登记

放 `assets/2d/<T-编号>-<名称>/`：定稿图、`prompts/<文件名>.txt`（每轮实际用的提示词）、`来源.md`（工具、参考图、授权）、`生图记录.json`（每轮的源文件、哈希、参考图）、物件清单、坐标 json；草稿与迭代放 `drafts/`、`review/`。生成与定稿用 `tools/art/art.py gen / promote / register`，登记到 `assets/登记表.csv`。新图加完后运行 `python3 tools/art/level_previews.py` 更新按关卡浏览的预览页。规则见 [`assets/README.md`](../../assets/README.md)。

派给队友时用 `/task-card` 写任务卡（照 T-041、T-042、T-043 的格式：交付物表、规格、逐张画什么、验收清单、兜底），存 `docs/任务/`。

**过门**：平面与真实尺寸对得上；效果图的每个镜头能对上需求文档的机位；用户看过。

## 4. 阶段 C：Blender 建模

### 4.1 两条路

| | 庄园里的房间 | 独立关卡（火车、回廊、尾声、演绎小关卡） |
| --- | --- | --- |
| 源文件 | `assets/3d/manor/manor.blend`，原位建在庄园坐标上 | `assets/3d/<id>/<id>.blend` |
| 版本 | 状态层（子集合），不复制空间 | 集合 `<ID>_MODEL` / `REVIEW_ONLY` |
| 脚本 | `assets/3d/manor/scripts/1x_room_<id>.py`，开头 `exec` `room_lib.py` | `assets/3d/<id>/scripts/NN_*.py`；墙、门、家具尽量复用 `room_lib.py`、`room_props.py`，和庄园保持同一种做法 |
| 细则 | [房间模块 SOP](房间模块SOP.md) 第 1—5.5 节 | [关卡开发规范](关卡开发规范.md) 阶段 3 |

### 4.2 开工

1. 输入盘点：平面、效果图（≥ 3 个朝向）、剧情物件表、状态表，见房间模块 SOP 第 1 节。
2. 把布置写进需求文档（家具靠哪面墙、坐标、为什么），要用户拍板的先问。
3. 写下这次的目标与验收清单（第 1 节第 1 条），大项目分阶段：庄园是先墙体结构，再立面与造景，室内最后。

### 4.3 后台迭代（4—6 轮）

每轮：脚本另存到 `/tmp` 后渲染（不碰正式 `.blend`）→ 和每张效果图同视角出“参考 | 白天 | 夜晚”对照 → 挑一两个最影响观感的问题修 → 跑体检。房间模块的命令见房间模块 SOP 第 4 节，那里还有一张“踩过的坑”表（色温、线性底色、法线强度、灯光强度、单面件）。

**过门**：第 5.6 节的体检目标全部达到；对照图用户看过。

## 5. 建模规范（防穿模与几何异常）

用户 10-14 指出缺面与穿模后定下的规矩，之后每个房间都按此验收（10-16：“不要出现穿模以及几何体相关异常”）。

### 5.1 几何

| 规则 | 数字 |
| --- | --- |
| 实体不缺面 | 缺面边 0 条（墙面饰面、布、纸这类单面件除外） |
| 共面重叠（z-fighting，Godot 里会闪斜纹） | 一个房间合计 < 0.01 m²；房间与庄园外壳之间 0 |
| 平行的两个面 | 间距 ≥ 2 mm |
| 贴墙、贴天花的件（帘杆托架、灯座、壁灯） | 离饰面 ≥ 1 mm；线脚顶面低于天花 |
| 同一件家具里几块板的端面 | 错开 2—5 mm，或一块插进另一块；不要端面平齐 |
| 两根料相接 | 首尾相接，不交叉穿过（中立板不伸进背板、门扇中梃不穿中冒头） |
| 门窗套内沿与洞口贴面 | 错开 2 mm |
| 凹多边形（拱形开口等） | 先拆成凸块再拉伸，否则三角化出错 |
| 植物叶片卡片 | 每片随机倾斜几度，不全平行 |
| 单面件的法线 | 朝玩家看的一侧；顶面、墙面法线朝室内。需要时加厚度（train 车顶翻转法线朝内、加 2.5 cm 厚） |

### 5.2 摆放

| 规则 | 说明 |
| --- | --- |
| 放在完成面上 | 地上的东西放在地面完成面上（温室是石板面，不是庄园地坪）；站在地毯上的家具放在地毯面上（+1.15 cm）；地毯只铺在真正放东西的范围 |
| 不穿进固定结构 | 墙、矮墙、窗框、玻璃里不能有物件（温室那次整排花盆穿过玻璃） |
| 不悬空 | 搁板、花架木条下面要有托梁 |
| 通道 | 门的开启扇形里不放家具；通道宽 ≥ 0.6 m；先留出门与门之间的路线，其余东西靠墙、成行，不在地上随手散放 |
| 窗帘 | 落地窗帘占墙前约 0.15 m；靠窗家具离墙 ≥ 0.45 m，或改用短帘 |
| 状态层 | 会被状态层占用的位置，基础空间里不放东西；检查时按“空间 + 该层”逐层叠起来查 |
| 家具朝向 | 局部坐标正面朝 -y；靠北墙 0°、南墙 180°、西墙 90°、东墙 -90°（暗房工作台转反过一次） |
| 剧情物件 | 必须看得清：全黑相纸泡在深色药液里看不见，就加白边、浮在液面上 |

### 5.3 碰撞（可走动的关卡）

| 规则 | 说明 |
| --- | --- |
| 地面、墙、大件家具 | 网格名加 `-col`，Godot 导入时自动生成碰撞 |
| 没有实体但要挡人的地方 | 单独做 `<房间>·碰撞-colonly`（Blender 里设为线框、不渲染） |
| 门扇 | 要有碰撞；原点在合页轴上；能开的门名字以“门”结尾，打不开的带“（锁着）”等括号说明 |
| 邻屋 | 玩家走得进去的邻屋（门开着或没门扇），在关卡场景里作为 `邻·<房间>` 实例进来；某个模块接管了庄园的部件（楼梯等），所有看得见那里的关卡场景都要带上它 |
| 楼梯 | 不用做斜坡碰撞，`player.gd` 能直接迈上 0.32 m 以内的台阶 |

### 5.4 材质

- 底色写线性值，不是 sRGB：深色木头约 0.07（≈ sRGB 0.3）。
- 带贴图的材质会忽略底色；要换色的布料只用法线贴图 + 底色。
- 法线强度：家具木纹 0.12、墙面 0.15，再高就像橘皮。
- 单面件不和要重算法线的件共用一个部件（用别名材质键 `wallf`、`linenf`）。
- 渗漏效果的白模由程序替换，只做正常版本。

### 5.5 命名

- 物体名 `<房间>·<物件>`；剧情物件名字写清楚，方便用户在 Godot 里对着摆 `hs_`。
- 要单独换画面的面（窗外风景）单独一个网格并命名，UV 铺满 0—1。
- 想单独替换的小物件不进整体模型，在 Godot 里用 `prop_<编号>` 占位。

### 5.6 体检命令与目标

| 体检 | 命令 | 目标 |
| --- | --- | --- |
| 几何体检 | `$B -b /tmp/room.blend --python scripts/09_check_geometry.py`（查不出是哪对面时用 `09b_overlap_detail.py -- "<物体名>"`） | 5.1 的缺面与共面重叠数字 |
| 排布体检 | `$B -b /tmp/room.blend --python scripts/23_layout_audit.py -- <名>` → `排布体检.json` + `排布俯视.png` | 穿进固定结构、物件互相穿插、卡片穿出墙或玻璃、超出房间都为 0；悬空逐类看，只修真的；俯视图通道留空 |
| Godot 碰撞 | `godot --headless --path godot --script res://tools/probe_collision.gd -- --level=<id> --x=<X范围> --z=<Z范围> --step=0.5` | 在一片网格上向下打射线，走得到的地方都没有 `----`（下面是空的） |
| Godot 行走 | `godot --headless --path godot --script res://tools/probe_walk.gd -- --level=<id> --dirs=8` | 用玩家本身向各方向走，不掉下去；楼梯上下各走一遍 |
| 大地图连通 | `godot --headless --path godot -- --probe-map --group=<组>` | 从客房走得到每个房间和每个任务目标 |

以上 Blender 脚本在 `assets/3d/manor/scripts/`，命令细节（备份与还原庄园的体检结果）见房间模块 SOP 第 5、5.5 节。独立关卡还没有专用体检脚本：第一个用到的独立关卡（回廊）把 `09`、`23` 改一份放进 `assets/3d/<id>/scripts/`，再补进本节。

## 6. 阶段 D：在用户的 Blender 里执行并保存
