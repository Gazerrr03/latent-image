# 09 团队协作与任务派发

更新日期：2026-10-12

## 1. 前提（用户 10-12）

- 用户主导整个项目，用 coding agent 负责全部代码。
- **最坏情况下，其余队友什么都做不了。** 计划必须在只有用户 + agent 的情况下也能完成。
- 队友是额外产能：用户要能在需要时，把自己的想法转成详细、具体、可验收的任务交给他们。队友不需要理解游戏开发，只需要知道“交什么、交成什么样、放在哪”。

## 2. 分工原则

| 原则 | 做法 |
| --- | --- |
| 代码只有一个人碰 | Godot 工程只由用户（和 agent）修改，队友不碰，避免冲突和沟通成本 |
| 内容是“填表”和“交文件” | 队友的产出是表格的行、按命名约定导出的文件，管线自动接入 |
| 每个任务都有兜底 | 每张任务卡写明：如果没按时交，用户 + agent 用什么替代（灰盒、CC0 素材、AI 生成、从分镜提取） |
| 先交草稿再精修 | 每个任务设一个 24 小时内的检查点，先交粗糙版本确认方向 |
| 验收是一张清单 | 任务卡写清楚检查哪几条，满足即算完成，避免反复返工 |

## 3. 从想法到任务：派发流程

```
用户的一句需求（可以很粗）
   ↓  让 Claude Code 用 /task-card 生成任务卡
任务卡草稿（docs/任务/T-xxx.md）
   ↓  用户检查：目的对吗？验收标准能检查吗？兜底可行吗？
发给队友（直接转发任务卡文件或复制内容）
   ↓  24 小时内交草稿
用户按验收清单检查 → 通过 / 退回并注明哪条不满足
   ↓
交付物放进 incoming/ 或 content/，管线导入，任务卡状态改为“完成”
```

- 任务卡模板：[任务/_模板.md](任务/_模板.md)。
- 任务总表：[任务/README.md](任务/README.md)。
- 生成任务卡的命令：项目内的 `/task-card` 技能（`.claude/skills/task-card/`）。用法：在 Claude Code 里输入 `/task-card 我想要书房的 3D 模型，给美术`，agent 会读取相关设计文档，生成一张完整的任务卡。

## 4. 队友交付的内容类型

| 类型 | 格式 | 放在哪 | 规范 |
| --- | --- | --- | --- |
| 剧情 / 文本 | 表格的行（CSV 或在线表格） | `godot/content/story/` | 《05》写作规范；表头见《06》第 2 节 |
| 3D 小物件 | `.glb`（保留 `.blend` 源文件） | `godot/art/props/` | 第 5 节；尺寸按检查报告“小物件规格” |
| 纸质道具与 UI 图 | PNG | `incoming/images/` | 文件名 = 任务卡中给定的 id |
| 声音 | WAV 或 OGG | `incoming/audio/` | 文件名 = 声音 id |
| 参考图 | 任意图片 | `docs/参考图/<房间名>/` | — |

不会用 Git 的队友：把文件放进共享网盘的同名文件夹，由用户每天同步一次。

## 5. 关卡与 3D 模型的分工（10-14 起）

**房间空间不再交模型。** 关卡空间与机位构图由用户在 Godot 编辑器里搭成 `godot/levels/<房间id>.tscn`，这是空间的唯一依据；节点命名约定（`spawn`、`cam_<机位>`、`hs_<编号>`、`chr_<人名>`、`prop_<编号>`）见《填表说明 1.4》。

美术做的是**从关卡反推出来的资产**：

| 规则 | 说明 |
| --- | --- |
| 小物件 | 关卡里每个 `prop_<编号>` 占位方块就是一件小物件；尺寸以检查报告“小物件规格”一节为准 |
| 单位与原点 | 米；1 Blender 单位 = 1 米；**原点放在底面中心**，正面朝 Blender 的 -Y（进 Godot 后朝 +z） |
| 文件 | 一件物件一个 `.glb`（保留 `.blend` 源文件），交到 `godot/art/props/`，在模型资产表 `content/visual/props.csv` 登记 |
| 可检查物件 | 物件要能被检查时，由用户在关卡里给它套一个 `hs_<编号>` 节点，美术不用管 |
| 碰撞 | 需要挡住玩家的物件，网格名后加 `-col`（Godot 导入时自动生成碰撞体） |
| 灯光 | 模型不带灯光；灯光在关卡场景里 |
| 材质 | 每个材质单独命名；渗漏变体由程序替换材质，美术只做正常版本 |
| 规模 | 单件建议 2 万面以内，贴图 1K—2K |

整间房的 Blender 模型（旧做法）可以作为参考或贴图来源，但不再直接作为房间使用。

## 6. 只有用户 + agent 时怎么完成

| 工作 | 兜底做法 |
| --- | --- |
| 3D 房间 | 用户在 Godot 里用 CSG 方块搭关卡 + CC0 家具素材（Poly Haven 等）；渗漏变体本来就是白模，不浪费 |
| 标志性道具 | CC0 素材修改，或 Blender 中简单建模（打字机可用简化造型 + 好材质） |
| 纸质道具 | 游戏内实时排版渲染文字 + 纸张纹理；Codex 生成纸张底图 |
| 预写文本 | 分镜 PDF 已含大部分文本，agent 直接提取成表格 |
| 声音 | CC0 音效库 + 自录 |
| 参赛材料 | agent 根据设计文档起草，用户修改 |

这意味着队友的产出全部用来**提高品质**，而不是决定能否完成。
