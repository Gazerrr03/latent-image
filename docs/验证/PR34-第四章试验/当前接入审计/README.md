## 文档与验证的偏差

- `模块清单.json` 把 M01-CAM 列为可测，但 X01/X02 仍写暂缓；实际代码已经包含举镜与收人。
- README 将 M02 改名为空间微调，JSON仍定义为记录本与今年笔记；同一文档还保留 M00“没有地下室”旧说明。不能靠模块编号或 tested 字样判断当前实现。
- 本轮未见可核实的人工验收结果，不将 tested/ready 视为用户最终接受。
- `test_ch4_cellar_camera.gd` 直接发信号/调用方法并设置目标年份，不能证明正常键鼠、步行、射线命中和任务激活都通畅。
- `test_ch4_continuous.gd:40` 使用 `director._running`，当前 Director 定义的是 `running`；不能把该脚本存在当成连续流程已验证。
- `Director._do(cellar_gameplay)` 在自动模式直接调用 `autoplay_cellar()` 设1920已收走并发完成信号。自动通关只能证明跳过玩法后的叙事连接，不能证明相机玩法可玩。
- 需要实测的接线风险：inspect(camera)结束后会清空活跃热点；cellar_gameplay阶段只写清单并等待信号，未见显影盘重新激活。相机测试直调显影方法绕过了这个问题。这里是静态风险，本轮未替代人工试玩下故障结论。
