# PR34 模块渐进接入计划

日期：2026-10-22。适用工作区：`codex/chapter4-pr34-trial`。
状态：计划，尚未执行本计划中的新接入；人工验收不预填通过。
依据：[当前接入审计](当前接入审计/README.md)。PR 固定为 `0f688ba0551762acde2e32a2d54523cf5ad28d7b`。

## 目标与边界

目标是让玩家在第四章调查中理解被忘记的人、主人的动机和星期四的安排，并自然进入第五章。PR 提供的空间、阅读与相机操作是实现候选；不以复刻原型全部功能作为验收标准。

当前已有空间、调查热点、入口返回和简化摄影玩法。计划从这些实现继续，不重复搬入原型玩家/UI/完整关卡脚本，也不覆盖其他进行中的本地改动。

流程固定为：一个补丁 → agent基础检查 → 可启动的人工试玩版本 → 用户反馈 → 修正或接纳 → 下一个补丁。未获人工接纳时不自动堆叠后续行为。归档文档可独立处理，但不在用户试玩过程中改动该试玩版本。

## 接入顺序

### P0 固定当前检查点与模块账本

- 清点当前未提交文件，将已经存在的空间、调查接线、相机规则与启动入口标为“已有实现，待人工验收”；核对可分离范围后保存本地检查点，不合入主分支。
- 统一 README 与模块清单：M02 保持“记录本与今年笔记”，空间微调单独登记；X01/X02 改为“实验实现已存在，产品验收待定”。不把 tested 或文件存在改写成人工通过。
- 为每个检查点记录提交、启动入口、变化和待测问题。使用独立提交回退，不建立通用插件系统或复杂运行时开关。
- 产物：可信的当前状态表、可恢复基线、人工试玩说明。

### P1 稳定当前摄影与出入流程（M01-CAM，先修再加）

范围：不增加新谜题，验证和修复已接入内容。

- 从正常第四章入口走到地下室，确认四组调查、拿相机、F/滚轮/快门、两次显影、梯子返回均由正常输入完成。
- 核查显影盘在摄影阶段是否属于活跃热点；阶段变更时同时更新实际可交互目标和清单，避免只改提示。
- 检查物品检视、阅读、暂停期间相机热键不会误触；离开关卡后相机UI/FOV清理正常。
- 纠正连续测试脚本的 running 字段引用；自动通关保留为叙事连接检查，另用真实输入检查摄影关键操作，不用直接调用方法宣称人工流程已验证。
- 温室照片Q引导作为独立小修复处理：终点应是可到达、可交互站位；不混成地下室新玩法。

人工检查：是否随时知道下一步；显影盘和梯子能不能找到、按E是否生效；失败后是否能恢复；摄影循环的往返是否值得。

继续条件：当前流程无阻断，且用户明确决定保留什么。若用户不认可“主动收人”，先把该段移回独立试验，不让后续主线补丁依赖收人完成。

### P2 阅读与动机信息（M02）

- 补历年记录、第二次年度合影后被收走的规则、今年保护她的决定、谋杀立案的理由、星期四安排、“我请了一个会把它查清楚的人”。仅从现行《02》取内容；缺少具体月份等细节时不自行编造。
- 修正“家里空无一人”等与现行剧情不一致的表述；不提前写出受邀者身份或第五章提示词。
- 先用本地 inspection_pages/统一检视做多页阅读；PR 记录本底图和翻页表现按需要拆取。不接“必须读第4/7页才能操作”的门槛，不再占用已有 Tab 笔记本键位。
- 把本模块新增剧情文字放内容表；接触到的相机提示可随相关补丁逐步移出硬编码，不为此全面重构关卡。

人工检查：不看开发说明，能否说清“谁记得、谁被忘记、主人为什么安排案件”；翻页、退出、复查是否自然。

继续条件：信息能被理解，阅读成本可接受。记录本是否动态解锁新页由本次试玩结果决定。

### P3 剪报与旧物（M03）

- 增加独立 hs_cellar_clip 和可阅读剪报，呈现“意外死亡，不予追查”及划线。
- 对照钢笔与教案、围裙、板球帽逐件核对模型和位置；缺哪件补哪件，不把泛用报纸捆或文字提示算成完整实物。
- 将旧物与第二章名字及主人记录对应；审查是否需要新的证据卡，不为任务检测制造无推理用途的卡。

人工检查：能否认出这些是曾住过的人留下的东西；剪报是否让主人动机更清楚；是否有信息重复或难发现。

### P4 入口前置与返回（M04）

- 在夜拍照片或门闩线索达到现行剧情要求后，园丁松口并指向花盆；不一开始就同时开放所有任务入口。
- 实现花盆/活板门的实体状态与最小操作反馈，避免正文说挪开了、场景却没发生变化；不擅自扩展长动画。
- 最小范围解决任务列中“前置依赖”与“结束自由探索”混用的问题。优先评估现有门锁/房间状态能否表达局部入口；若必须加字段，就明确区分两种含义并回归所有原任务，避免凭编号写死通用任务逻辑。
- 区分入口解锁、进入、核心调查完成；不能在按入口的一刻就把核心调查算完成。
- 明确梯子是否允许提前返回、以及重入行为。保留当前“收人后才允许离开”或改成自由返回是产品取舍，不能由接线方式决定。

人工检查：能否从园丁的话找到入口；未解锁时反馈是否清楚；下去、上来、再进入是否合理。

### P5 章节收尾与恢复（M05）

- 用调查内容完成条件衔接回客房，不改变 D4 已定推论；r4和批注承接主人动机及对灵媒的疑问，保留园丁带话和“我睡下了”。
- 当前试验入口继续不读写正式存档。另用独立试验存档测试恢复：调查前、读完笔记、拿相机、第一次显影后、地下室完成后，逐个确认不误判或卡死。
- 若摄影保留，保存最小必要进度并从进度重建UI；可推导的状态不重复存。若摄影不进入主线，就只持久化调查和出入状态。
- 依次验收地下室直通、完整第四章、进入第五章；内容校验和两种自动通关作为基础检查，再交用户进行连续人工试玩。

人工检查：能否形成下一章的问题；读档后是否知道自己做到哪；是否需要重看或重复操作过多。

继续条件：第四章主线人工接受。至此即可作为一个完整交付范围，不必等待所有可选原型模块。

### P6 建模来源与验证材料归档（无玩法变化）

- 按PR源清单归档62个建模/来源/审查文件，保留提交与来源，不导入原型project.godot或重复音频/字体。
- 将Windows绝对路径改成明确的项目输入输出参数或项目内相对路径；先检查脚本依赖，不直接在用户正在编辑的Blender场景中重建。
- 能否完整重建需要单独验证；仅完成归档时标“已归档，重建未验证”。
- 原型测试只迁移与采用行为有关的断言和截图工具。

本项可以在不改变试玩版本时提前完成，不作为 P2—P5 的阻塞条件。

## 第四章主线接受后，按价值选择的独立试验

| 顺序 | 候选模块 | 要验证的收益 | 成本与停止条件 |
| --- | --- | --- | --- |
| O1 | 动态记录本解锁页 | 玩家能把刚观察到的变化与旧记录联系起来 | 复用同一阅读入口；若只是反复跑桌子看教程就不采用 |
| O2 | 实体干版/片夹 | 装片操作让摄影机制更有实物感、因果更清楚 | 增加缺片、装回、错误年份状态；若只是增加往返，保留当前R简化 |
| O3 | 连续处理1922/1924 | 每个年份提供新人物信息或新的观察结果 | 不把同一套操作重复三次作为默认要求；没有新增信息就不强制 |
| O4 | 钥匙与底片盒 | 提供有意义的空间发现，服务1926信息 | 若仅为延长流程而开锁，不接；可以独立决定，无需强绑O3 |
| O5 | 1926实体底片、主人反射与双结局 | 比较“保留/拍摄”选择对玩家理解的影响 | 最后讨论；必须先定义这段是幻象、重演还是改变事实，以及如何回到第五章；不能改写已定死因和终局 |

依赖：P0→P1→P2→P3→P4→P5；P6可独立归档。O1/O2在主线接受后分别试验；O3需要明确是否继续多年份操作；O4可单独做有价值的发现，但若仅服务双结局则与O5一并评估；O5在相关规则确认后才做。

## 实施前的产品检查点

1. **已有收人玩法**：保留为主线必经、保留为可选试验，还是改为观察历史？P1试玩后决定；计划不将现有代码当成已获产品接受。
2. **调查与离开**：是否允许提前返回？地下室信息若是第五章必经前提，应限制章末推进，而不一定要把玩家锁在地下室。
3. **1926的当前普通收人行为**：现版已把1926放进普通haunted年份；不能等到实现双结局才处理其含义。P1确认玩法边界时一并决定是否限制该年份。

尺寸调整另列空间反馈补丁；不要在同一轮同时改房间大小、阅读内容和摄影步骤，否则人工反馈难以归因。
