## 为什么做

游戏按“分镜即数据”运行：分镜 PDF 的每一行要变成表格的一行，程序才能播放。所有预写文本也是 AI 失败时的兜底，必须一字不差、符合事实锚点。见《06-技术方案》第 2 节、《05》写作规范。

## 交付物

一份在线表格（或 CSV），含三个工作表，导出后放进 `godot/content/story/`（现有表格已由 agent 填好 A 线，可在此基础上补 B、C 线和标为“待补”的回答）：

| 文件 | 每行是什么 | 列 |
| --- | --- | --- |
| `shots.csv` | 分镜中的一个镜头 | shot_id, node, line, scene, camera, mode, sound, text, ai_slot, actions, next, note |
| `lines.csv` | 一句按条件出现的台词 | set_id, condition, speaker, text |
| `annotations.csv` | 预设批注、追问、理由、终局选项 | set_id, text, tendency, note, response |

列的含义见《06》第 2.1 节。`camera`、`scene`、`sound` 不确定时可以先用中文描述，程序会统一改成 id。

## 规格

- 覆盖分镜 PDF 中 N1 到 N7 的所有镜头，包括 A、B、C 三条线和 N5 的六种组合。
- `text` 列照抄分镜“文字与界面”一栏；标注 [AI] 的地方，在 `ai_slot` 列填槽位类型（嫌疑人口吻 / 追问回答 / 报纸 / 预设批注 / 案卷自述）。
- `actions` 列根据“玩家与系统”一栏，从白名单中选：`wait`、`inspect`、`collect`、`annotate`、`inquire`、`accuse`、`link`、`use_telegram`、`leak`、`goto`、`ending_choice`。拿不准就用中文写清楚，交给程序处理。
- 发现分镜前后矛盾时，不要自行修改，在备注列写明。已知的矛盾见《02》第 8 节。

## 验收清单

- [ ] 每个镜号都有一行，镜号与 PDF 一致，没有遗漏
- [ ] 所有台词、文件文字与 PDF 一字不差
- [ ] 每个节点的最后一个镜头都有 `use_telegram`
- [ ] 每个 [AI] 标注都填了 `ai_slot`
- [ ] 每组预设批注都有三条，并标注倾向变量

## 不需要做

- 不需要写新剧情或改写台词。
- 不需要设计镜头。

## 兜底

截止未交付：agent 直接从 PDF 提取生成三张表，用户核对。
