# 文本、批注与异常空间：游戏设计文档

最后更新：2026-10-05

本文档随讨论持续更新。用于保存设计共识、初步设想和待决问题，不表示所有内容已经定稿。作品名称暂未确定。

阶段与内容模块的实施提案见 [阶段与模块路线图](阶段与模块路线图.md)。具体排期与阶段范围待讨论确认。

## 1. 作品方向

### 已确定

- 创作一款以好玩、有趣为首要目标的空间游戏。
- 用户为建筑设计专业，空间设计应参与核心体验。
- 不考虑硬件。
- 基于已有小说开展二创，当前文学来源为《树叶之屋》（House of Leaves）。
- 借鉴原作围绕原始材料不断整理、批注、再批注的多层叙事结构，具体故事不必照搬原作。
- 气质偏科幻、荒诞；主要活动是阅读、探索空间与互动。
- 采用互动数字叙事（IDN）思路，并保留类跑团的自由表达和尝试感。
- 玩家无需扮演约翰尼或其他指定角色，玩家就是读者本人。此条取代此前“玩家扮演手稿整理者”的提案。
- 基础界面是文本阅读器；不同叙述者的批注通过不同字体区分。
- 特定文段与批注段可以作为可交互的 slot，玩家点击后参与互动。
- 玩家可以根据材料产生联想，自由写下自己的批注，也可以进入第一人称 3D 空间体验。
- 提供与当前情境有关的 prompt suggestions，帮助玩家表达与推进体验；保留自由输入。
- 基础书房也会发生异变。用户以《树叶之屋》的爪痕为参照，将体验描述为“空间的模因污染”。
- 类型为心理惊悚。剧情仿照《树叶之屋》的结构规划，人物与事件原创。
- 核心规则为“描述即建造”：被描述的空间会成立；后来的描述能改写之前的记录；否认会让事物消失并连带抹去记录；描述会沿读者传播。规则不在游戏中明说。
- 编剧是新设角色：他的文字以方括号场景提示呈现，写下即成立，也是机制在故事内的解释。
- 沉浸空间中，未被描述的部分以白模／线框呈现。
- 具体剧情草案见《剧情大纲.md》；人物使用带隐喻的外文名。
- 前期做成 Web 小游戏：WebGL（three.js 渲染库），不使用游戏引擎。后续更精细的 3D 工作另行讨论。
- 第一章原型位于 `game/`，运行方式与模块说明见 `game/README.md`。

### 尚未定稿

- 故事目标、篇幅、游戏时长、章节数量与结局（草案见《剧情大纲.md》）。
- AI 的具体职责、模型、开发工具与实现方式。
- 二创中原作人物、专名、文本的使用范围，以及参赛授权与材料要求。

## 2. 叙事材料与读者身份

借鉴的结构：原始记录 → 作者／研究者写成手稿 → 整理者批注 → 后续编辑批注。用户此前以纳维森记录、赞帕诺、约翰尼及后续编辑说明这一结构。

读者自己的批注可以成为新增的一层材料。不同层的材料可能彼此回应、矛盾，并出现不遵循线性时间的关系。

当前不规定哪一层绝对真实，也不规定玩家每句话都能直接改写世界。

“编剧”已确认为新设角色，见 1. 节。各叙述层的具体人物见《剧情大纲.md》。

## 3. 当前两种空间设想

以下是用户初步提出的两类空间。它们是否是独立关卡、常驻场景或循环进入的状态，尚未确定。

### 3.1 基础房间：书房与电脑

**用户设想**

- 一个小型书房，中间有办公桌。
- 玩家视角是坐在桌前看电脑。
- 电脑显示手稿阅读界面，感觉像在网站中浏览小说。
- 阅读器可以查看正文、不同角色的批注和小说评论区。
- 评论信息可能来自其他真实玩家，也可能来自虚构角色。
- 书房本身也会异变，阅读者所处的空间将参与体验。

**待明确**

- 书房能否自由走动，还是以坐在桌前阅读为主？
- 日常阅读时，屏幕占据整个游戏画面，还是一直保留电脑边框与书房视野？
- 书房中的异常怎样被发现，是否提供可调查的线索？
- 评论区使用真实异步玩家内容、预写内容，还是两者结合？
- 评论区、页边批注、脚注之间有什么区别？玩家自己的内容出现在哪里？

### 3.2 沉浸房间：进入文字指向的空间

**用户设想**

- 通过特定文段或批注进入第一人称 3D 体验。
- 空间会随着批注内容发生变化。
- 探索与互动是这一部分的主要体验。

**待明确**

- 哪些批注能够影响空间：已有角色批注、当前玩家批注、评论，还是其中一部分？
- 批注何时生效：提交后立即变化、再次进入时变化，还是通过额外操作激活？
- 空间变化的范围是什么：声音、光线、物件、门、路径、布局或事件？
- 玩家进入后有什么具体目标，可以做哪些有趣的动作？
- 如何返回阅读器？空间中的发现如何进入文本与批注？
- 不同段落进入同一空间的不同版本，还是不同空间？

### 3.3 书房异变与“空间的模因污染”

**已确定**

- 返回书房不意味着回到始终不变的环境。
- 书房异变是游戏体验的一部分；用户用“空间的模因污染”描述其气质。
- 这一表述目前不等于已确定的世界观解释、感染数值或传播机制。

**设计提案，尚待用户判断**

- 让书房异变与读过的文字、批注或沉浸空间中的经历产生可辨认的联系。
- 例如：在沉浸空间见过的划痕，在返回后出现在书房门框上。此例为助手提出，未确定为剧情。
- 可以逐步从痕迹、声音发展到空间关系变化；不预设固定阶段或顺序。
- 书房异变可以提供新的调查机会，使阅读、探索和返回形成互相影响的体验。

**待明确**

- 哪种行为会触发异变：阅读、批注、进入空间，还是具体探索行动？
- 痕迹是永久保留、可改变，还是仅在某些叙述版本中存在？
- 玩家能否主动调查书房异常，以及调查结果如何回到文本？
- 异变是否有明确解释，还是保留多种可能的理解？

## 4. 文本阅读器与可交互 slot

### 已确定的作用

- slot 附着于具体的文段或批注段。
- 点击 slot 后，玩家可以围绕该段文字展开联想、批注或进入空间。
- 字体用于区分叙述与批注的来源。

### 待明确的交互

- 如何提示一段文字可以交互，以及如何避免提示破坏阅读？
- 一次点击后直接进入空间，还是先展开批注、建议与操作入口？
- 是否允许给任何文字写批注，还是先限于已设计的 slot？
- 建议是完整可用的句子、可改写的开头，还是调查方向？
- 同一 slot 是否允许重复调查、追加批注、编辑旧批注？

## 5. Prompt suggestions 与自由输入

### 已接受的方向

借鉴《1001 夜》把自由表达接到明确游戏目标和可执行结果的思路，在本作增加情境相关的输入建议，帮助玩家继续体验。

### 设计建议，待验证

- 建议应与选中的文本和已发生的体验有关。
- 玩家可以使用建议、修改建议或自由输入。
- 建议不宜直接泄露谜底，也不宜让玩家只剩照着点的体验。
- 输入建议只能帮助引导；可执行的空间变化仍需有明确规则。
- AI 的叙述与实际场景应一致：描述某扇门出现时，空间里应确实有对应变化。

## 6. 当前体验循环草案

阅读正文与多层批注 → 点击感兴趣的 slot → 联想、提问或写批注 → 进入关联空间 → 探索与互动 → 返回可能已异变的书房与阅读器 → 查看或补充材料 → 再次进入。

该循环是对讨论的整理，尚未规定每步的强制顺序。尤其“先批注还是先探索”仍保持开放。

## 7. 下一轮优先讨论

1. 围绕一段具体文本，设计一个完整的 slot：点开后看到什么、可以输入什么、怎样进入空间。
2. 设计一次批注造成的空间变化，明确其好玩之处及玩家如何发现。
3. 设计第一次返回书房时的异变及其后续互动，再决定第一个原型范围。

暂不锁定此前助手提出的“测绘改变房屋”、固定房间数、固定结局数、玩家身份及暂定名称。
