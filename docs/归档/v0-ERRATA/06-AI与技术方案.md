# 06 AI 与技术方案

更新日期：2026-10-12

## 1. 技术选型

- 【已确定】（2026-10-05）前期做网页小游戏：Vite + TypeScript + three.js（WebGL 渲染库），**不使用游戏引擎**。
- 【已确定】更精细的 3D 工作以后另行讨论。
- 【待决】（2026-10-09）用户提出考虑用 UE 等游戏引擎提升视效与演出，同时也提到时间、人手不足，且不熟悉引擎。见 Q10。

选择网页的理由：

- 阅读器本身就是网页，用 HTML/CSS 实现排版与字体最直接；
- 评委打开链接即可游玩，无需安装；
- 场景几何简单（走廊、房间、白模），three.js 足够；
- 声音和贴图都能用代码生成，不依赖素材管线。

## 2. 模块结构【已实现】

| 文件 | 职责 |
| --- | --- |
| `src/director.ts` | 场景切换、第一章事件流程（批注生效、返回异变、收尾） |
| `src/state.ts` | 游戏状态与本地存档（localStorage，键名 `errata.save.v1`） |
| `src/content/chapter1.ts` | 第一章文本：叙述层、slot、随状态变化的段落、评论、输入建议 |
| `src/reader/reader.ts` | 阅读器网页与 slot 面板 |
| `src/intent/` | 意图解析接口；`ruleResolver.ts` 是临时关键词规则 |
| `src/scenes/study.ts` | 书房：阅读／环顾模式、划痕异变 |
| `src/scenes/corridor.ts` | 走廊：第一人称、白模／材质、门的三种状态、丈量、黑暗中数数 |
| `src/scenes/common.ts` | 白模材质、轮廓线、程序化贴图 |
| `src/audio.ts` | WebAudio 合成音效 |
| `src/hud.ts` | 提示、字幕、淡入淡出、菜单 |

运行与操作见 `game/README.md`。

### 游戏状态（关键字段）

- `door.status`：`bare`（原始）／`described`（被描述）／`denied`（被否认），以及门牌号、颜色。
- `recordedLength`：被写进记录的走廊长度；`measuredLength`：玩家量到的最远距离。
- `annotations`：玩家写过的全部批注及其意图。
- `revisions`：哪些段落在何时被修订，用于显示修订标记。
- `lastSteps`：上一次在黑暗中走的步数。
- `flags`：划痕、看到划痕、幽灵批注、章节完成等事件开关。

新章节沿用同一模式：**文本是状态的函数**，状态变化后重新渲染页面，被改写的段落自动打上修订标记。

## 3. AI 的职责与边界

### 原则

- 【已确定】AI 负责理解玩家的话，在情境中回应；**关键房间、状态、线索、动作和结局由设计者写好**。
- 【已确定】AI 的叙述必须和场景一致。
- 【提案】AI 的输出不是自由文本，而是“从设计好的结果中选一个，并填入参数”。

### 批注解析接口【已实现接口，规则为临时实现】

```
输入：slotId、玩家原文、上下文（门的状态、量到的长度……）
输出：意图列表（describe / deny / measure / ask / note）
      + 门的新状态（状态、门牌号、颜色）
      + 新的走廊长度
      + 一行场景提示 【场景：……】
```

- 当前 `RuleResolver` 用关键词识别，只能验证流程，**不能证明自由语言体验成立**。
- 【提案】接入大模型时实现同一接口（如 `LLMResolver`），模型只返回上述结构化结果；场景提示可以由模型按惠特克的口吻生成，但必须描述已选定的状态。
- 【提案】保留规则解析作为离线和失败时的兜底，保证评审现场断网也能玩。

### AI 可能扩展的位置

| 用途 | 价值 | 风险 | 建议 |
| --- | --- | --- | --- |
| 批注意图理解 | 高：让自由输入真正成立 | 低：输出受限 | 参赛版本优先做 |
| 惠特克的场景提示生成 | 中：回应更贴合玩家原话 | 中：可能说出与场景不符的内容 | 限定模板与长度 |
| 情境输入建议 | 中 | 低 | 可选 |
| 评论区虚拟读者 | 中：网站更“活” | 中：内容不可控、剧透 | 第二章以后再看 |
| 多周目追加正文 | 用户期望（10-09） | 高：可能破坏剧情一致性 | 见 Q3，建议改为“玩家批注进入下一周目” |

### 待定的工程问题

- 【待决】模型与服务商、API 密钥放在哪里（纯前端无法安全保存密钥，需要一个很小的后端或代理）。
- 【待决】等待模型回应时的表现（例如阅读器显示“对方正在输入”或场景提示逐字出现）。
- 【待决】参赛提交的形式：在线网址、离线包，还是两者都提供。
- 【待决】AI 使用说明（参赛材料可能要求）。

## 4. 部署

- `npm run build` 输出到 `game/dist/`，是纯静态网页，可部署到任何静态托管服务。
- 若接入模型，需要额外一个转发接口（如 Serverless 函数）保管密钥。

## 5. 已知技术债

- 第一章的事件流程写死在 `director.ts`；第二章开始前建议把章节流程抽成数据或独立模块。
- 项目目录不是 Git 仓库，无版本历史。【提案】尽快 `git init`，便于回退和多人协作。
