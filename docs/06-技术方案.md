# 06 技术方案

更新日期：2026-10-12

状态：引擎 Godot【已确定】；其余为【提案】，搭工程当天验证。

## 1. 选型

| 项目 | 选择 | 理由 |
| --- | --- | --- |
| 引擎 | Godot 4.7（本机已装 4.7.2） | 轻量；场景和脚本都是纯文本，coding agent 可以直接读写；UE 团队无人熟悉 |
| 语言 | GDScript | Godot 原生，资料多，agent 熟悉 |
| 3D 素材 | Blender（本机已装）→ `.glb` | Godot 直接导入，命名约定可自动生成碰撞与交互 |
| AI | 大模型 API，经一个很小的转发服务调用 | 密钥不进游戏包；断网时用缓存与预写兜底 |
| 发布 | 桌面版（macOS / Windows）为主，Web 版为辅 | 比赛要求提交可运行文件；Web 版便于分享 |
| 版本管理 | Git + GitHub 私有仓库 | 回退、备份、多人协作 |

旧的 three.js 原型（`game/`）不迁移代码，取舍见第 7 节。

## 2. 核心思路：分镜即数据

分镜 PDF 的每一行（镜号、画面与镜头、声音、文字与界面、玩家与系统）几乎可以原样变成一行数据。程序只实现一个“分镜播放器”，按行执行，剧情内容全部写在表里。好处：

- 改剧情、加镜头不改代码；
- 用户可以把需求直接写成表格的一行；
- 队友的工作可以收敛为“填表”。

### 2.1 镜头表 `godot/content/story/shots.csv`

| 列 | 含义 | 示例 |
| --- | --- | --- |
| shot_id | 镜号 | `N2-A-01` |
| node | 节点 | `N2` |
| line | 分支线：`*`（共同）/ `A` / `B` / `C` | `A` |
| scene | 场景 id | `register_closeup` |
| camera | 机位或运镜预设名 | `close_slow_push` |
| mode | `camera`（镜头）/ `walk`（行走） | `camera` |
| sound | 声音 id，多个用 `;` 分隔 | `pen_scratch;typewriter_return` |
| text | 屏幕文字（预写兜底） | 簿边多一行小字：“已收悉” |
| ai_slot | AI 槽位类型，空则不调用 | — |
| actions | 系统动作，见 2.2 | `leak(L1);wait(4)` |
| next | 下一镜号，或条件分支 | `N2-A-02` |

### 2.2 系统动作白名单

镜头表只能调用这些动作（定义在 `godot/core/actions.gd`）；新增动作需要程序实现，这条线由用户（程序负责人）把关。另有 `objective(文字)`：在画面上方显示当前的开放式问题，空参数表示清除。

| 动作 | 说明 |
| --- | --- |
| `wait(秒)` | 无操作等待 |
| `inspect(hs_id)` | 允许检查某物件，检查后可能收入证据 |
| `collect(evidence_id)` | 获得证据 |
| `annotate(set_id)` | 弹出一组预设批注（三选一 + 短输入） |
| `inquire(set_id)` | 问话：对每人追问一句 |
| `accuse(reason_set)` | 在访客簿上指认，决定分支线 |
| `link(group)` | 证据板连线判定 |
| `use_telegram()` | 用掉一张电报纸，节点推进 |
| `leak(level)` | 设置渗漏等级，切换材质、词表、界面 |
| `goto(scene)` | 切换场景 |
| `ending(台词组)` | 终局：取主导属性作为视角（`view`），从台词组中按 `view=` 条件播放一条（10-13 替代原 `ending_choice` 三选一） |
| `say(set)` | 按条件播放 lines.csv 中的台词（如 N5、N6 按 X/Y/Z 变化的台词） |
| `confession()` | 播放案卷自述（目前为兜底版本） |
| `fx(预设)` | 切换媒介滤镜（`content/visual/fx.csv`）；`fx(自动)` 跟随渗漏等级 |
| `reveal(名称)` / `conceal(名称)` | 显示 / 隐藏布局表里的东西 |
| `sign(提示)` | 终局签名（访客簿） |
| `footage(片段)` | 播放影像片段（`content/visual/footage.csv`） |
| `osd(样式,文件名,编号,时间)` | 档案卡 / 取景器叠加在实时画面上；`osd()` 关闭 |

### 2.3 其他数据表

| 表 | 内容 |
| --- | --- |
| `evidence.csv` | 证据 id、名称、图片、对应结论（C1/C2/C3）、来源物件 |
| `links.csv` | 哪两件证据连起来算对，对应哪条结论、触发哪段回应 |
| `annotations.csv` | 每组预设批注的三条文本及对应的人格属性（好奇 / 记忆 / 共情 / 欲望） |
| `lines.csv` | 台词：说话人、文本、条件（例如 X=巴洛），用于 N5、N6 这类按组合变化的台词 |
| `wordlists.csv` | 词表闸门（见《05》） |
| `scenes.csv` | 场景 id、对应 `.glb` 或 Godot 场景、各渗漏等级的材质方案 |

## 3. 游戏状态

| 变量 | 说明 |
| --- | --- |
| `node` / `shot` | 当前节点与镜号 |
| `telegrams_left` | 剩余电报纸（7 → 0） |
| `accused` | 已指认的人与顺序（X、Y），Z 由此推出 |
| `line` | 当前分支线 A / B / C |
| `evidence` | 已获证据 |
| `links_done` | 已完成的连线（C1/C2/C3） |
| `leak_level` | 当前渗漏等级 L0—L4 |
| `tendency` | 人格属性计数（好奇 / 记忆 / 共情 / 欲望）；`dominant()` 取最高者，平局取好奇；条件里写作 `view` |
| `ending` | 终局视角（结束时的主导属性） |
| `container` | 本局随机的容器编号，镜头文字里的 `{容器号}` 会被替换 |
| `journal` | 玩家全部批注与选择（终局自述的输入） |

开发期提供调试面板：跳到任意镜号、切换分支线、设置渗漏等级、重置存档。这也是演示时的保险。

## 4. 工程结构

```
godot/
├── core/          game_state（状态与存档）、content_db（读表）、director（分镜播放器）、actions（动作白名单）
├── world/         scene_host（场景、机位、热区、渗漏材质）、greybox_specs（灰盒规格）、player（第一人称）
├── ui/            ui_root（界面层）、evidence_board（证据板）、register_view（访客簿）、media_fx（滤镜层）、footage_player（影像档案播放器）、debug_panel（F1）
├── shaders/       leak_white（渗漏 L3—L4 的白模网格）、cork（软木板）、media_fx（胶片/录像带/数字故障滤镜）、static_noise（雪花屏）
├── content/story/ 所有表格与文本
├── art/rooms/     美术模型（.glb）
└── tools/         validate_content（内容校验）
incoming/          队友交付区（导入前的原始文件）
```

计划中尚未建立的模块：打字机纸页（预设批注）、文件阅读视图、`ai/`（槽位调用、词表闸门、缓存）。

### 4.1 验证命令

改动后由 agent 自己运行，详见根目录 `CLAUDE.md`：

| 命令 | 作用 |
| --- | --- |
| `--script res://tools/validate_content.gd` | 内容校验：镜号、动作、热区、证据、连线、台词、场景互相对得上 |
| `-- --autoplay` | 无界面自动通关，检查是否到达终局、电报纸用完、三组连线完成 |
| `-- --capture=<镜号>` | 跳到镜号截图后退出，用于自查画面 |

## 5. AI 原生开发方式

- **Claude Code**：主力，负责 Godot 工程、GDScript、导入管线、文档维护。
- **Godot MCP**：让 agent 自己运行游戏、截图、查看场景树，从而能自己验证改动。候选：[Coding-Solo/godot-mcp](https://github.com/Coding-Solo/godot-mcp)（安装最简单，能运行项目、读取调试输出）、[slangwald/godot-mcp](https://github.com/slangwald/godot-mcp)（支持运行、截图、编辑场景树、点击 UI）。在 Godot 4.7 上实测后选一个。
- **命令行**：`godot --headless` 用于导入、运行检查脚本与自动测试，agent 可以直接调用。
- **Codex**：生成概念图、纸质道具初稿、空间 UI 素材。
- 工程根目录写 `CLAUDE.md`，记录约定（动作白名单、命名规则、何时用 MCP、何时直接改文件），让每次新会话都遵守。

## 6. 技术风险

| 风险 | 对策 |
| --- | --- |
| Godot MCP 在 4.7 上不稳定 | 退回命令行 + 截图脚本；MCP 只是加速，不是依赖 |
| 美术模型迟迟不到 | 先用灰盒跑通；清空变体本身就是白模风格 |
| 模型 API 在现场断网 | 缓存 + 预写兜底，断网也能完整演示 |
| 中文字体渲染 | 选定一款可商用的中文衬线体与打字机风格英文字体，尽早嵌入测试 |
| Web 导出兼容性 | 以桌面版为主要交付物，Web 版为辅 |

## 7. three.js 原型的取舍

| 原型中的东西 | 处理 | 去向 |
| --- | --- | --- |
| 白模 + 轮廓线 + 网格地面（“未被描述的部分”） | **借鉴，已移植** | `shaders/leak_white.gdshader`，用作渗漏 L3—L4 的“露底”材质 |
| 第一人称步幅计数、数步数 | **借鉴，已移植** | `world/player.gd` 的步幅计数，之后用于“脚步声循环” |
| 坐在桌前阅读 / 抬头环顾两种模式 | **借鉴思路** | 镜头模式与行走模式 |
| 文本是状态的函数、段落被改写时打修订标记 | **借鉴思路** | 渗漏：同一段文字的称呼随节点等级变化 |
| 意图解析接口 + 临时规则兜底 | **借鉴思路** | AI 槽位 + 预写兜底 + 词表闸门 |
| HTML 阅读器页面、ERRATA 连载网站 | 舍弃 | 改为场景中的纸质文件与证据板 |
| 关键词规则解析器、“描述即建造”玩法 | 舍弃 | 新剧情改为指认与连线 |
| WebAudio 实时合成音效 | 舍弃 | 改用音效文件（`res://audio/<id>.ogg`） |
| 梣林巷 7 号的全部剧情文本 | 舍弃 | — |
