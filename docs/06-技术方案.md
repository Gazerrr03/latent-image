## 1. 选型

| 项目 | 选择 | 理由 |
| --- | --- | --- |
| 引擎 | Godot 4.7（本机已装 4.7.2） | 轻量；场景和脚本都是纯文本，coding agent 可以直接读写；UE 团队无人熟悉 |
| 语言 | GDScript | Godot 原生，资料多，agent 熟悉 |
| 3D 素材 | Blender（本机已装）→ `.glb` | Godot 直接导入，命名约定可自动生成碰撞与交互 |
| AI | 大模型 API，经一个很小的转发服务调用 | 密钥不进游戏包；断网时用缓存与预写兜底 |
| 发布 | 桌面版（macOS / Windows）为主，Web 版为辅 | 比赛要求提交可运行文件；Web 版便于分享 |
| 版本管理 | Git + GitHub 私有仓库 | 回退、备份、多人协作 |

旧的 three.js 原型（`game/`）不迁移代码，取舍见第 7 节。

## 2. 核心思路：分镜即数据

分镜 PDF 的每一行（镜号、画面与镜头、声音、文字与界面、玩家与系统）几乎可以原样变成一行数据。程序只实现一个“分镜播放器”，按行执行，剧情内容全部写在表里。好处：

- 改剧情、加镜头不改代码；
- 用户可以把需求直接写成表格的一行；
- 队友的工作可以收敛为“填表”。

**空间不进表（10-14）**：填表只用于只靠名字就能接上的内容（线索、台词、小物件用哪个模型、声音、滤镜）。关卡空间与机位构图影响核心体验，由人在 Godot 编辑器里搭成关卡场景 `godot/levels/<房间id>.tscn`；表格与场景只靠节点名对上（`spawn`、`cam_<机位>`、`hs_<编号>`、`chr_<人名>`、`prop_<编号>`），约定见《填表说明 1.4》。镜头的节奏与运镜优先由 agent 完成。还没有关卡场景的房间暂按 `rooms.csv` + `layout.csv` 生成灰盒，全部搭完后删除。

### 2.1 镜头表 `godot/content/story/shots.csv`

| 列 | 含义 | 示例 |
| --- | --- | --- |
| shot_id | 镜号：`C章-序号`，尾声为 `EP-序号` | `C2-05` |
| node | 章：`C0`—`C7`、`EP` | `C2` |
| line | 保留列，一律填 `*`（主线只有一条） | `*` |
| scene | 房间 id（房间登记表） | `garden` |
| camera | 机位名：关卡场景里 `cam_<机位>` 节点（灰盒房间为布局表的机位行） | `vent` |
| mode | `camera`（镜头）/ `walk`（行走） | `walk` |
| sound | 声音 id，多个用 `;` 分隔；`id@秒` 延迟播放，`-id` 停掉循环声（解析见 `actions.gd` 的 `parse_sounds`）。台词表、可检查物件表的 sound 列同一写法：说这句话 / 检查这个物件时响 | `door_knock;door_bang@3.2;-projector` |
| text | 屏幕文字（人写兜底）；可用占位符 `{容器号}`、`{本轮陈述}` | 九点，我到达奥瑞尔庄园。 |
| ai_slot | AI 槽位类型，空则不调用（见 #2） | `人物口吻` |
| actions | 系统动作，见 2.2 | `objective(我自己：上星期四夜里，我在哪里？);inspect(hs_coat)` |
| next | 下一镜号；空 = 表格下一行；可写条件 `view=保护>C7-03|>C7-04` | `END` |

### 2.2 系统动作白名单

镜头表只能调用这些动作（定义在 `godot/core/actions.gd`）；新增动作需要程序实现，由用户（程序负责人）把关。`reveal` / `conceal` 属于布景动作，在镜头文字出现之前执行；其余动作在文字之后按顺序执行。

| 动作 | 说明 |
| --- | --- |
| `wait(秒)` | 无操作等待 |
| `objective(文字)` | 画面上方的开放式问题；空参数表示清除 |
| `inspect(hs_id,…)` | 允许检查这些物件，检查后可能收入证据；行走镜头里玩家自己走过去看，左上角列出各物件的观察提示（`hotspots.csv` 的 hint 列） |
| `collect(evidence_id)` | 获得证据 |
| `annotate(set_id)` | 打字机上的记录：一组预设三选一，每条可带倾向（保护 / 取代） |
| `inquire(set_id)` | 问话：选一个问题，听回答 |
| `say(set)` | 播放台词表 lines.csv 中的一组台词（可带条件） |
| `link(group)` | 证据板推论：组内任意一对线索连通即成立（docs/02 第 10 节的冗余规则） |
| `develop(图片)` | 第 6 章：亲手冲洗底片，图片放在 `art/footage/`（2026-10-13 新增） |
| `telling(set_id)` | 终局：两种讲法，倾向较高的一种先出现在纸上，由玩家选择；选定的话写入 `{本轮陈述}`（2026-10-13 新增） |
| `leak(等级)` | 设置渗漏等级 0—4，切换滤镜与材质 |
| `goto(scene)` | 切换场景 |
| `fx(预设)` | 切换媒介滤镜（`content/visual/fx.csv`）；`fx(自动)` 跟随渗漏等级 |
| `reveal(名称)` / `conceal(名称)` | 显示 / 隐藏关卡场景里的同名节点（灰盒房间为布局表里的东西） |
| `footage(片段)` | 播放影像片段（`content/visual/footage.csv`） |
| `osd(样式,文件名,编号,时间)` | 档案卡 / 取景器叠加在实时画面上；`osd()` 关闭 |
| `recap(set)` | 章间黑场前半段“梦”：上一章的复盘，台词表的一组逐行浮现，先出的行渐暗；占位符 `{今日线索}` `{今日推论}` `{今日记录}` 按本章填入，空则整行不出现；影像片段表有 `梦_<组名>`（如 `梦_r1`）时先播这段梦境动画（2026-10-17 新增，同日改为梦） |
| `diary(set)` | 章间黑场后半段“日记”：新一章开头的日记本一页，台词表的一组，说话人 `日期` / `天气` / `标题` 填进对应位置，说话人空着的行是标题下的小字（2026-10-17 新增） |
| `music(曲名[,秒])` | 播放配乐（`content/audio/music.csv`，文件在 `godot/audio/music/`），循环，跨镜头、跨房间一直放；`music(关闭[,秒])` 淡出，秒数填 0 为直接切断；默认淡入 / 淡出 1.5 秒。与 reveal 一样在本镜文字出现之前执行（2026-10-17 新增） |
| `explore(组)` | 自由探索：把玩家放进庄园大地图，按任务表 `content/story/quests.csv` 这一组给提示、等玩家触发（交谈、走进房间、推门、检查物件），触发后播放这条任务的镜头，播完回到原地继续走；写了 require 的收尾任务完成后回到镜头表的下一镜。自动通关时按表格顺序做完（2026-10-17 新增） |
| `corridor()` | 第 5 章演绎·回廊：进入唱针玩法（声音只在走动时响，停下就停，往回走倒放；推开尽头的门进下一层）。每层内容在 `content/story/corridor.csv`，空间与规则在 `levels/ded_corridor.gd`；走完把每层 `collect` 列的线索收进证据板，继续下一镜。自动通关时直接收线索跳过（2026-10-18 新增） |
| `anim(人物,动作)` | 方盒子人物播放动作：`idle`（站立）/ `walk` / `talk` / `tap`（敲两下桌面）/ `sit`；人物写全名或台词里的简称。`tap` 播完自动回到站立。台词表 `say` 时说话人自动播 `talk`，说完回到 `idle`（2026-10-17 新增） |

10-13 删除：`use_telegram`（电报）、`accuse` / `sign`（访客簿）、`ending` / `confession`（四种视角与案卷自述）。

## 3. 游戏状态

| 变量 | 说明 |
| --- | --- |
| `shot` | 当前镜号 |
| `evidence` | 已获证据 |
| `found_at` | 每条证据在哪一镜收进来（章末复盘与检视用） |
| `inspected` | 已检查的物件 |
| `links_done` / `link_pairs` | 已成立的推论组与连上的线索对 |
| `leak_level` | 当前渗漏等级 L0—L4 |
| `tendency` | 记录的倾向计数（保护 / 取代）；`dominant()` 取较高者，平局取保护；条件里写作 `view`；命令行 `--view=取代` 可强制 |
| `ending` / `statement` | 终局选定的讲法与那句话 |
| `container` | 本局的容器编号 01—12；镜头与物件文字里的 `{容器号}` 会被替换 |
| `journal` | 玩家的全部记录与选择 |

存档版本为 2；旧剧情（版本 1）的存档读到后作废，从头开始。

开发期提供调试面板（F1）：跳到任意镜号、按章跳转、切换倾向、设置渗漏等级、重置存档。这也是演示时的保险。

## 4. 工程结构

```
godot/
├── core/          game_state（状态与存档）、content_db（读表）、director（分镜播放器）、actions（动作白名单）、settings（设置与音量总线）
├── world/         look（共用天光）、ambience（灰尘、火星、雨丝）、scene_host（读关卡场景或搭灰盒、机位、热区、渗漏材质）、player（第一人称；准星对着能开的门按 E 开关，门的逻辑在 scene_host；胶囊抬高 0.32 m，脚下一根向下的分离射线，台阶与楼梯直接走上去）
├── levels/        人工搭的关卡场景（<房间id>.tscn），空间与构图的唯一依据
├── ui/            ui_root（界面层、冲洗底片、章末黑场、准星提示、房间名、日期角标）、menus（标题页、暂停页、设置、操作说明）、hud_text（从表格拼界面文字）、evidence_board（证据板、检视）、evidence_card（卡片样式）、media_fx（滤镜层）、footage_player（影像档案播放器）、debug_panel（F1）
├── shaders/       sky_panorama（天空盒）、leak_white（渗漏 L3—L4 的白模网格）、cork（软木板）、media_fx（胶片/录像带/数字故障滤镜）、static_noise（雪花屏）
├── content/story/ 所有表格与文本
├── art/props/     小物件模型（.glb，模型资产表登记）
├── art/look/      天空全景与扫描材质（CC0，来源见 来源.md）
└── tools/         validate_content（内容校验）、probe_collision / probe_walk（关卡碰撞与行走体检）
incoming/          队友交付区（导入前的原始文件）
```

计划中尚未建立的模块：打字机纸页、文件阅读视图、上下文模块（槽位挑选、词表闸门、Agent 生成与兜底，见 #2）。

### 4.1 验证命令

改动后由 agent 自己运行，详见根目录 `CLAUDE.md`：

| 命令 | 作用 |
| --- | --- |
| `--script res://tools/validate_content.gd` | 内容校验：镜号、动作、热区、证据、连线、台词、场景互相对得上 |
| `-- --autoplay` | 无界面自动通关，检查是否选定了一种讲法、六组推论全部成立；加 `--view=取代` 走另一种讲法 |
| `-- --capture=<镜号>` | 跳到镜号截图后退出，用于自查画面；自由探索时加 `--at=x,y,z,朝向[,俯仰]` 把玩家放到某处；加 `--menu=标题|确认|暂停|设置|操作` 截界面 |
| `-- --probe-map [--group=c1]` | 大地图体检：搭起庄园大地图、门全开，按碰撞烘寻路网格，检查从客房能不能走到每个房间的出生点和这一组的每个任务目标 |

## 5. AI 原生开发方式

- **Claude Code**：主力，负责 Godot 工程、GDScript、导入管线、文档维护。
- **Godot MCP**：让 agent 自己运行游戏、截图、查看场景树，从而能自己验证改动。候选：[Coding-Solo/godot-mcp](https://github.com/Coding-Solo/godot-mcp)（安装最简单，能运行项目、读取调试输出）、[slangwald/godot-mcp](https://github.com/slangwald/godot-mcp)（支持运行、截图、编辑场景树、点击 UI）。在 Godot 4.7 上实测后选一个。
- **命令行**：`godot --headless` 用于导入、运行检查脚本与自动测试，agent 可以直接调用。
- **Codex**：生成概念图、纸质道具初稿、空间 UI 素材。
- 工程根目录写 `CLAUDE.md`，记录约定（动作白名单、命名规则、何时用 MCP、何时直接改文件），让每次新会话都遵守。

## 6. 技术风险

| 风险 | 对策 |
| --- | --- |
| Godot MCP 在 4.7 上不稳定 | 退回命令行 + 截图脚本；MCP 只是加速，不是依赖 |
| 美术模型迟迟不到 | 关卡场景先用 CSG 方块搭；小物件保留占位方块；清空变体本身就是白模风格 |
| 模型 API 在现场断网 | 缓存 + 预写兜底，断网也能完整演示 |
| 中文字体渲染 | 选定一款可商用的中文衬线体与打字机风格英文字体，尽早嵌入测试 |
| Web 导出兼容性 | 以桌面版为主要交付物，Web 版为辅 |

## 7. three.js 原型的取舍

| 原型中的东西 | 处理 | 去向 |
| --- | --- | --- |
| 白模 + 轮廓线 + 网格地面（“未被描述的部分”） | **借鉴，已移植** | `shaders/leak_white.gdshader`，用作渗漏 L3—L4 的“露底”材质 |
| 第一人称步幅计数、数步数 | **借鉴，已移植** | `world/player.gd` 的步幅计数，之后用于“脚步声循环” |
| 坐在桌前阅读 / 抬头环顾两种模式 | **借鉴思路** | 镜头模式与行走模式 |
| 文本是状态的函数、段落被改写时打修订标记 | **借鉴思路** | 渗漏：同一段文字的称呼随节点等级变化 |
| 意图解析接口 + 临时规则兜底 | **借鉴思路** | AI 槽位 + 预写兜底 + 词表闸门 |
| HTML 阅读器页面、ERRATA 连载网站 | 舍弃 | 改为场景中的纸质文件与证据板 |
| 关键词规则解析器、“描述即建造”玩法 | 舍弃 | 新剧情改为指认与连线 |
| WebAudio 实时合成音效 | 舍弃 | 改用音效文件（`res://audio/<id>.ogg`） |
| 梣林巷 7 号的全部剧情文本 | 舍弃 | — |

## 8. 界面与设置（10-18）

- **入口**：`main.gd` 读存档后打开标题页（`ui/menus.gd`），由标题页调用 `Director.start()`；自动通关与截图不经过标题页。走到结尾仍是“再读一遍”。
- **回到标题**：先 `GameState.save()`，再 `Director.stop()`——与调试面板跳镜号同一套打断（`ui.cancel()` + 发 `inspected(CANCEL)`），等播放器停下，不发 `finished`；然后收起玩家、停掉循环声和配乐，打开标题页。调试面板跳镜号时，标题页与暂停页自己收起。
- **暂停**：Esc 由 `ui_root._unhandled_input` 处理，只在玩家自由行走（`player.active` 且没被冻结）、没有文字框、选项、证据板、冲洗、黑场、影像档案时打开；暂停只冻结玩家，不暂停场景树（播放器此时在等玩家触发，没有在计时）。`player.gd` 不再处理 Esc。
- **设置**：autoload `Settings`（`core/settings.gd`），存 `user://settings.cfg`。音量分三条总线 Master / Music / SFX，声音节点加进场景树时按文件自动分线（`res://audio/music/` 下的是 Music），播放声音的代码不用改；鼠标灵敏度与 Y 轴反转由 `player.gd` 读取；文字速度由 `ui_root.show_text` 读取；亮度是 `media_fx` 着色器最后一步的 gamma，只作用于 3D 画面；全屏 / 窗口在截图、自动测试、无界面时不改。
- **文字**：界面上的字都在界面文字表 `content/visual/ui.csv`（id、text、note）；日期角标、标题页“继续调查”下面那行、房间名由 `ui/hud_text.gd` 从镜头表、台词表的日记页、关卡表、房间表拼出来，代码不写死。
- **准星提示**：`player.gd` 照旧传“E　检查：药柜”这样的文字，`ui_root.set_hint` 统一排成键帽 +“动作 · 对象”，交谈只写名字。

## 9. 画面：天光、材质、氛围粒子与性能（10-19）

视觉基准是《Hitman 3》Dartmoor 庄园（Hilde Sunde 的环境作品）：颜色收敛但分得出冷暖，大面积暗、局部亮，陈旧感来自材质与光，不靠滤镜染色。调整顺序：灯光与天空 → 材质 → 氛围粒子 → 最后才调滤镜。

- **天光（`world/look.gd` + `content/visual/look.csv`）**：所有庄园房间共用一套天空、日光 / 月光、远处的雾与室内灯倍数。按当前章日记里“天气”那一行找第一条 `match` 命中的预设（入夜 → 夜，雾、雨、阴、晴），没写天气时用“默认”（阴天）。每个房间以自己机位环境为底（环境光强度、SSAO、SSIL 照旧），只换天空、雾和色调；机位环境带 `metadata/own_look = true` 的（暗房、火车）原样使用。换章时 `scene_host._on_state_changed` 重新套一遍。
- **天空盒（远景）**：一张 CC0 全景（`art/look/stuttgart_hillside_2k.hdr`，`shaders/sky_panorama.gdshader`），白天、夜里、雨天共用，只改亮度与色调，远处的山和树林不再是模型。`manor.gltf.import` 跳过 `远景_山丘`、`远景_树林` 两个物体（`manor.blend` 里仍保留，重新导出不受影响）；近处的树、绿篱、围墙仍是模型，走动时有前后错动。环境光与反射取自天空，冷色补光有了来源。
- **材质（`art/look/materials/*.tres`）**：画面里面积最大的几种（灰泥墙、墙裙漆、灰绿木作漆、橡木地板、桃花心木、深色木、黄铜、草坪）换成带粗糙度图的扫描材质。文件名 = glTF 里的材质名，`tools/apply_material_overrides.py` 写进各 `.gltf.import` 的外部材质覆盖，Blender 重新导出不会冲掉。来源与许可见 `art/look/来源.md`。
- **暗房红灯开关**：调查日（C1-01—C6-03）暗房进门是黑的，走廊门边的开关 `sw_红灯` 由玩家开关红灯，没有白灯（房间状态表不再开白灯）。关卡节点 `sw_<层名>` 由 `scene_host._bind_switch` 接上：自由行走时描边，按 E 切换 `层·<层名>`，元数据 `hum` 的嗡鸣只在灯亮、玩家在这个房间时响。截图可加 `--switch=红灯`。
- **氛围粒子（`world/ambience.gd`）**：室内光里飘的灰尘（受光材质，只在有光处看得见；渗漏 L3 起停）、名为“炉火”“烛光”的点光旁的火星与火光跳动、室外下雨时的雨丝。都跟着当前相机，数量很少。
- **滤镜**：`L0`—`L2` 的低饱和改由“去色”承担，“泛黄”只留一点，冷窗光与暖灯分得开；自由行走时（`media_fx.set_exploring`）颗粒 65%、闪烁 50%、片门抖动 35%、划痕 30%、灰尘 50%，剧情镜头与具名预设按原强度。
- **性能**：目标是重点场景不低于 45 帧（每帧 22.2 ms）。最贵的是阴影：太阳的阴影每帧把整座庄园再画几遍，改为两层、24 米（`look.gd` 运行时设置，关卡场景不改）；点光阴影改为双抛物面（画 2 遍而不是 6 遍），截图对比看不出差别。抽样命令与结果见 `docs/验证/2026-10-19-帧率/`；`tools/probe_fps.gd` 可加 `--no-vsync`（看真实余量）、`--day`、`--off=dust,fog,sky,shadows,sun,ssil`（关掉某项看开销）、`--shots=目录`（每个房间截一张）。
