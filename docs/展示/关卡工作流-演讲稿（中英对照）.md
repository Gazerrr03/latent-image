# 关卡与建筑工作流 / Level & Architecture Workflow

演讲稿，中英对照，6 页，约 5 分钟。
Talk script in Chinese and English, 6 slides, about 5 minutes.

---

## 1 · AI 在这里做了什么 / What AI did here

**画面 / On screen**：左边是 Blender 里的庄园模型，右边是 Godot 里走进同一个房间。
Left: the manor model in Blender. Right: walking into the same room in Godot.

**中文**

我们用 AI 做了两件事。

第一，从零搭出关卡空间，从平面图、效果图到 Blender 建模、导出，整条链路由 AI 执行，人负责定方向和验收。

第二，让搭好的模型变成可以浏览的版本：在 Godot 里补上最基础的移动和视角，让人能走进每个房间，看清空间本身。

下面讲具体流程。

**English**

We used AI for two things.

First, building level spaces from scratch, from floor plans and renderings through Blender modeling and export. AI carried out the whole chain; humans set direction and signed off.

Second, turning the finished models into something you can browse: in Godot we added basic movement and view, so anyone can walk into each room and see the space itself.

Now, the pipeline.

## 2 · 六步流程 / The six-step pipeline

**画面 / On screen**：A 空间需求 → B 预览图 → C Blender 建模 → D 存档 → E 进 Godot → F 试玩
A Space brief → B Previews → C Blender modeling → D Archive → E Into Godot → F Playtest

**中文**

关卡生产分为六步：先写空间需求，即这个空间的用途、可活动范围、真实尺寸和摆放物件；再出预览图；在 Blender 里建模；把工作文件存档；导入 Godot，放好出生点和机位；最后试玩。每两步之间设一道关口，未达标不进入下一步。空间和镜头由人拍板，出图、建模和检查交给 AI 执行。

**English**

Level production has six steps. First, a space brief: what the space is for, how far people can move through it, its real dimensions and what objects it holds. Then preview images, Blender modeling, archiving the working file, importing into Godot with spawn points and cameras, and finally playtesting. A gate sits between each pair of steps; nothing advances until it passes. Humans decide the space and camera; AI handles the drawing, modeling and checking.

## 3 · 预览图：先平面，后生图 / Previews: plan first, then image generation

**画面 / On screen**：客厅平面图 → 白模构图 → 效果图；作废的“过大”版本。
Living-room plan → gray-model framing → rendering; the rejected oversized version.

**中文**

生图模型常见的偏差是把房间画大、把家具画小。因此顺序固定：先用脚本画 1:50 平面图，并自动检查门的开启范围和通道宽度；再在 Blender 里摆白模，从各机位渲染一张构图底图；最后把底图、尺寸和家具清单一并写入提示词生图，不合格的单张重出。

原则是真实尺寸优先。客厅按真实尺寸放不下圆桌加沙发，我们没有缩小家具去迎合效果图，而是二选一，整套图重新出。

**English**

Image models tend to draw rooms too large and furniture too small. So the order is fixed: a script draws a 1:50 floor plan and checks door swings and walkway widths; we block out the room in Blender and render a framing shot from each camera; then the framing shot, dimensions and furniture list go into the prompt, and any image that fails is redrawn on its own.

Real dimensions come first. At true scale, the living room could not fit both a round table and a sofa set. Rather than shrinking the furniture to match the rendering, we picked one and regenerated the whole set.

## 4 · 建模：把质量变成数字 / Modeling: quality as numbers

**画面 / On screen**：庄园外观前后对比；944 m² → 0，42 → 0。
Manor exterior before and after; 944 m² → 0, 42 → 0.

**中文**

我们先把“做得精细”这类要求，转化为可检查的验收标准：几何零缺陷、与效果图同视角逐项对照、进游戏后效果一致。

庄园第一版出现破面后，我们写了体检脚本，扫描整栋建筑，测出 944 平方米的重叠面和 42 条缺面边。问题指向建模方法本身，于是改用布尔合并重建，两项都降为零。之后每一轮都从效果图的同一角度渲染对照，只修当下最影响观感的一处，顺序依次为几何、材质、凹凸细节、植物、生活痕迹，前后约十轮。所有操作都写成可重复运行的脚本，庄园目前有 38 个。

**English**

We first turn a request like "make it detailed" into checkable criteria: zero geometry defects, an item-by-item comparison with each rendering from the same viewpoint, and the same result inside the game.

When the first manor pass showed broken faces, we wrote an inspection script and scanned the whole building: 944 m² of overlapping faces and 42 edges with missing faces. The problem lay in the modeling method itself, so we rebuilt with boolean unions and brought both figures to zero. Each later round renders from the same angle as the rendering and fixes only the most visible problem, in this order: geometry, materials, relief detail, vegetation, signs of life. This took about ten rounds. Every operation is a rerunnable script; the manor currently has 38 of them.

## 5 · 一座房子只建一次 / One house, built once

**画面 / On screen**：同一个房间的三个状态层：原始 / 改动后 / 另一种布置。
One room's three state layers: original / altered / another arrangement.

**中文**

同一个房间可能有几种不同状态。我们不复制房间，因为副本必然逐渐对不上。每个房间只在建筑的真实坐标上建一次，不同状态做成叠在上面的图层，按需切换。游戏里也只有一份几何，包体更小，改一处即全局生效。

**English**

One room can exist in several states. We don't duplicate rooms, because copies inevitably drift apart. Each room is built once, at its real coordinates in the building. Different states are layers stacked on top and switched as needed. The game ships with a single copy of the geometry, so the build is smaller and one edit applies everywhere.

## 6 · 漂亮不等于能玩 / Beautiful is not playable

**画面 / On screen**：走不上去的楼梯、踩空的地板、穿过去的门、走不进去的房间。
Stairs you can't climb, a floor you fall through, a door you walk through, a room you can't enter.

**中文**

第一次真机试玩暴露的问题，在建模软件里看不出来：楼梯上不去、地板会踩空、门没有碰撞、游戏里的模型比 Blender 里的旧一个版本、某个房间走不进去。

因此试玩分两层。自动体检：让虚拟角色从出生点向八个方向行走，看是否会掉落；从入口出发，确认每个房间都可以到达；穿过每道门，确认画面没有跳变。此外，每次改动后都由人亲手走一遍。

**English**

The first real playtest exposed problems the modeling tool didn't show: stairs that couldn't be climbed, a floor players fell through, doors without collision, a game model one version behind Blender, and a room that couldn't be entered.

So playtesting has two layers. Automated checks: a virtual character walks in eight directions from the spawn point to catch falls; starting from the entrance, it confirms every room is reachable; and it crosses every door to make sure the image does not jump. In addition, after every change, a person walks through the game by hand.
