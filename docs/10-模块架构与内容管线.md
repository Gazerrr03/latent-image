# 10 模块架构与内容管线

更新日期：2026-10-13

架构图：[图/模块架构.html](图/模块架构.html)（用浏览器打开，右上角 `⋯` 可导出 PNG / PDF）。

## 1. 核心思路

**游戏规则只写一次，具体内容全部来自表格和文件。**

整个项目分成四层，从上往下流动：

| 层 | 是什么 | 谁负责 |
| --- | --- | --- |
| ① 内容生产层 | 表格（剧情、人物、线索、房间、音效、词表）和文件（模型、图片、声音） | 队友，可独立完成 |
| ② 导入与检查管线 | 把表格和文件读进来，核对彼此是否对得上，生成检查报告 | 程序（用户 + agent） |
| ③ 游戏运行层 | 照着表格播放剧情、运行调查玩法、搭房间、调用 AI | 程序（用户 + agent） |
| ④ 玩家看到与听到的 | 界面、3D 画面、声音、演出 | 程序搭框架，美术与声音成员决定品质 |

队友只需要关心第①层：**知道自己该填哪张表、交到哪个文件夹，填完运行一次检查，看报告有没有报错。**

## 3. 第②层：导入与检查管线

队友交来的东西，在这里依次经过五步：

| 步骤 | 做什么 | 发现问题时 |
| --- | --- | --- |
| 读取 | 读入所有表格和文件 | 报告哪张表格式不对 |
| 交叉核对 | 镜头里提到的物件、证据、台词、房间，在对应的表里找不找得到 | 报告“镜头 N3-A-01 提到的物件 hs_xxx 不存在” |
| 模型挂接 | 按命名约定，自动给模型里的物件加上交互、出生点、出口 | 报告“管家室模型缺少出口” |
| 检查报告 | 汇总所有错误和警告 | 有错误就不能合并进游戏 |
| 预览 | 在游戏里按 F1 跳到任意镜头查看效果 | — |

现状（10-13）：读取、交叉核对、检查报告、预览都已可用。检查报告是中文清单，写明“表格、位置、问题、怎么改”，队友双击仓库根目录的 `检查内容.command` 即可生成。模型挂接已写好，但还没有真实模型验证过。
