# 10 模块架构与内容管线

更新日期：2026-10-13（按暗房主线与 #3 迁移后的工程重写）

这篇回答三个问题：**现在开发好了哪些模块；队友能往哪里填内容；任务怎么分发、内容怎么生产和贡献。**

## 1. 核心思路

**游戏规则只写一次，具体内容全部来自表格和文件。**

| 层 | 是什么 | 谁负责 |
| --- | --- | --- |
| ① 内容生产 | 表格（剧情、人物、线索、房间、音效、词表）和文件（模型、图片、声音） | 队友，可独立完成 |
| ② 导入与检查 | 读表、交叉核对、中文检查报告、自动通关 | 程序（用户 + agent） |
| ③ 游戏运行 | 照着表格播放剧情、调查玩法、搭房间 | 程序（用户 + agent） |
| ④ 玩家看到与听到的 | 界面、3D 画面、声音、演出 | 程序搭框架，美术与声音成员决定品质 |

**代码只有用户和 agent 碰；队友只交表格的行和按约定命名的文件。**

## 4. 怎么分发任务

队友的任务分三类，派发方式一样：**一句需求 → 任务卡 → PDF 派发单 → 草稿检查点 → 验收 → 接入。**

| 类型 | 例子 | 任务卡写什么 | 派发 |
| --- | --- | --- | --- |
| **交文件** | 场景设计包、人物三视图、模型、图片、声音 | 文件名、格式、尺寸、命名约定、验收清单 | 已有 14 张，见 [任务/派发/派发清单](任务/派发/派发清单.md) |
| **填表** | 润色口吻、补问话、补候选线索、补词表 | 哪张表、哪些行、每列怎么填、不得违反 T1—T5 | 用 `/task-card` 生成，附上对应的填表说明页 |
| **设计** | 场景平面与效果图 | 功能需求，不替队友做设计 | 同“交文件” |

步骤：

1. **你说一句需求**，在 Claude Code 里输入 `/task-card <需求>`，例如 `/task-card 给第 2 章三个人的问话各补两个问题和回答，给文案`。agent 读设计文档，生成 `docs/任务/T-xxx.md`，登记到任务总表。
2. **你检查任务卡**：目的对吗？验收能逐条判断吗？
3. **生成派发单**：让 agent “把 T-xxx 做成派发 PDF”（工具：`python3 tools/dispatch/make_dispatch.py docs/任务/T-xxx.md`），得到一份去掉内部内容、附故事简介与共同基准的 PDF，输出到 `docs/任务/派发/`。
4. **点对点发出**，同时说清草稿检查点（派发后 24 小时）和截止。
5. **收草稿**，确认方向；**收终稿**，按验收清单逐条打勾。
6. **接入**（见第 6 节），任务总表状态改为“完成”。

一张卡只给一个人、一个交付主题；相互依赖的内容（例如暗房和花园的通风口）交给同一个人。

## 5. 队友怎么生产内容

### 5.1 交文件的人（美术、声音）

1. 读派发单：先读“为什么做”和附录里的故事简介，再看“必须出现”和验收清单。
2. 按派发单的**文件名**命名；3D 物体名遵守命名约定（可检查物件以 `hs_` 开头，名字就是派发单里的编号）。
3. 用了 AI 或网上素材，写进 `来源.md`。
4. **草稿检查点前发一版粗稿**，确认方向再细化。
5. 打包发给你。**不需要会 Git，不需要打开 Godot。**

### 5.2 填表的人（文案、策划）

1. 拿到表格：你从仓库导出那张 `.csv` 发给他，或放在共享网盘。
2. 用飞书多维表格、腾讯文档或 Google 表格打开编辑；第一行表头不要改；文字换行写 `\n`。
3. 只改任务卡指定的行和列；新加的编号只用英文字母、数字、下划线、短横线。
4. 导出为 **CSV（UTF-8）** 发回给你。
5. 写作规矩：人物台词克制、每句不超过 40 字；**侦探的旁白只省略、不说谎**；第 6 章之前不得出现“七点”；不出现“容器”“人格”和真实疾病名。

会用 Git 的队友也可以直接改 `godot/content/` 下的表，双击仓库根目录的 `检查内容.command` 看《检查报告》，有“错误”就改到没有为止，再交给你。

## 6. 内容怎么贡献进游戏（你 + agent 做）

| 交付 | 放到哪 | 接入方式 |
| --- | --- | --- |
| 表格 | 覆盖 `godot/content/<板块>/` 下的同名 `.csv` | 直接生效 |
| 房间模型 `.glb` | `incoming/models/` → `godot/art/rooms/room_<场景>.glb` | 房间登记表 `model` 列填路径 |
| 人物模型 `.glb` | `incoming/models/` | **等程序接入人物表 `model` 列** |
| 图片（叠印、合影、片头） | `godot/art/footage/` | 影像片段表 `image` 列或 `develop(...)` 填文件名 |
| 声音 | `godot/audio/` | 音效表 `file` 列填文件名 |
| 设计稿、三视图等参考 | `assets/2d/<任务编号>-<名称>/` | 在 `assets/登记表.csv` 登记 |

接入后让 agent 跑三条验证（见根目录 `CLAUDE.md`）：内容检查（0 错误）、两种讲法的自动通关、相关镜头截图。通过后由你提交。

最省事的做法：把队友交来的东西丢给 agent，说“这是 T-xxx 的交付，按验收清单检查并接入”。
