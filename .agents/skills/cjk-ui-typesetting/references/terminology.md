# 排版与文本布局团队沟通词典 (Typography Communication Guide)

本词典旨在帮助工程师、设计师与产品经理建立统一的专业语言，消除“这里看着有点奇怪”、“文字掉下去了”等模糊表述，准确指出排版缺陷的**根因**并给出**明确的工程落地建议**。

---

## 1. 核心排版缺陷术语对照表

| 中文术语 | 英文术语 | 典型视觉表现 | 产生根因 | 建议落地改法 |
| :--- | :--- | :--- | :--- | :--- |
| **孤行 / 孤字** | **Orphan / Widow** | 段落末尾、气泡翻页后或卡片底部，孤零零地留下一两个汉字或一个英文短词。 | 容器宽度触碰默认自动折行边界，未做尾部保护或两行长度平衡。 | **Web**: `text-wrap: pretty` 或在末尾两词间加 `&nbsp;`。<br>**Native**: 最小尾行字数约束（若末行字数 < 4，则从上一行借字）。 |
| **避头尾违规** | **Kinsoku Shori Violation** | 句号、逗号、问号、叹号或右括号独自落在下一行的第一个字符位置；或者左括号停在上一行最后一个字符。 | 渲染引擎缺少 CJK 标点避头尾法则支持（如原生 Canvas、简单字符串截断）。 | 引入避头尾检查：发现首字为避头标点时，将上一行末尾字一同强制推入下一行。 |
| **视觉失衡 / 粗糙折行** | **Ragged Line / Unbalanced Wrap** | 两行标题中，第一行占满（如 28 字），第二行仅有寥寥 2~3 个字，视觉重心严重倾斜。 | 传统排版策略只在行满时才折行，未进行多行总代价寻优。 | **Web**: 标题应用 `text-wrap: balance`。<br>**Native**: 两行平衡评分算法，惩罚行长度方差。 |
| **截断碎词** | **Arbitrary Word Slicing** | 英文单词、专业缩写或数字在行末被生硬拆开（如 `trans-` 换到下一行 `formation`）。 | 错误配置了 `word-break: break-all`。 | 改用 `word-break: normal; overflow-wrap: break-word;`。 |
| **居中抖动** | **Center-Alignment Jitter** | 打字机逐字输出时，由于文本居中对齐，每敲出一个字，整行文字都在向左抖动移位。 | 动态把单字追加（Append）到居中容器，触发了重排（Reflow）与重心重算。 | 预先完整赋值并确定容器宽度，通过 `visible_characters` 或遮罩 Reveal，杜绝位移。 |
| **描边透明度穿透** | **Outline Alpha Bleed / Ghosting** | 在打字机或渐隐效果中，文字颜色 Alpha 为 0 时，描边（Outline/Shadow）依然被强制画出，导致全句黑色鬼影。 | 渲染管线对 `font_outline` 或 `text-shadow` 未继承字体颜色的 Alpha 通道。 | 禁用纯透明度文字截断，改用字符数显隐控制（`visible_characters`）或 Canvas 像素裁剪。 |
| **击锤光标脱节** | **Caret Desynchronization** | 打字机跟随光标（`▌`）飘在文字上方、落后于正在敲击的字符，或在换行时未能准确落入次行行首。 | 光标坐标基于粗略字符索引乘固定宽度计算，未真实测算动态字体字偶距与行高。 | 依据排版引擎测算的实际行高与当前行前缀物理宽度（`get_string_size`）精确定位光标。 |

## 2. 团队沟通场景提词卡（直接复制使用）

### 场景 A：给前端同伴提 PR Review / Issue

> **标题**: `[Fix/UI] 优化移动端卡片标题折行，消除单字孤行`
>
> **描述**:
> 当前在部分屏幕宽度下，卡片标题末尾会出现单字成行（Orphan）的现象，第二行仅有 1 个汉字，视觉上较为松散且破坏了卡片下边缘平衡。
>
> **建议修改**:
> 1. 建议在标题 CSS 类中增加 `text-wrap: balance`（在现代浏览器下可自动平衡两行字数）。
> 2. 针对兜底兼容，可在动态渲染时将标题末尾两个词之间拼接 `&nbsp;` 或 Word Joiner，确保末尾词不被单个字打散。

---

### 场景 B：与 UI/UX 设计师对齐排版规范

> **反馈内容**:
> “关于主页 Banner 与 Modal 弹窗的双行标题，目前发现当文本长度在 20~26 字之间时，容易出现首行极长、次行仅有 2~3 字的视觉失衡（Ragged Wrap），且偶尔有标点符号落入次行首位（违反 CJK 避头尾）。
>
> 我们计划在前端引入两行对称平衡断行逻辑（保证次行字数不低于首行的 60%，且严格避开逗号句号落首行）。请确认这种视觉折行方案是否符合视觉规范？”

---

### 场景 C：AI 对话流 / 打字机组件重构需求

> **需求描述**:
> “当前 AI 对话气泡在逐字输出时存在明显的横向居中抖动，并且光标未能与当前吐字末尾对齐。
>
> **技术准则要求**:
> 1. **严禁拼接字符串驱动居中布局**：请预先测算或预占完整文本容器，通过原生步进可见字符数（`visible_characters`）或宽度裁剪控制流式显现。
> 2. **光标坐标测算**：打字机击锤光标需依据当前所在行的实际行宽与行高进行绝对定位。
> 3. **标点呼吸停顿与跳过机制**：逗号处增加 1.5 倍停顿，句号/叹号增加 3 倍停顿；点击气泡时立即跳过流式直显整页。”

## 3. 避头尾字符权威清单 (Kinsoku Character Reference)

### 避头字符（Line-Start Forbidden）
绝不能单独出现在一行最开头的符号：
```text
!%),.:;?]}¢°’”‰′″℃、。々〉》」』】〕〞〟ゝゞ・ヽヾ！％），．：；？］｝～…—
```

### 避尾字符（Line-End Forbidden）
绝不能单独停留在上一行末尾的符号：
```text
$([\{£¥‘“〈《「『【〔〝﹙﹛﹝＄（［｛
```
